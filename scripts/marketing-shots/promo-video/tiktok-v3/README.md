# DoneAt · TikTok v3 · 三个开头

三条中文竖屏短片，各 43.5 秒，1080×1920、60 fps。开头 6 秒不同，之后共用同一段故事和结尾。

第一版约 23 秒，节奏过快：界面特写一闪而过，起身动作也显得突兀。这一版把开头放宽到 6 秒，每个界面特写都留出能读完的停留，起身和走路重新按真实的身体动作做了。

## 一句话故事

> 一个打工人不停地看时间，却看不出今天还剩多少；有了 DoneAt 之后，午饭、犯困、临近下班，他都能一眼看到进度，最后准点关掉电脑回家。

画面顺序跟着人物的一天走：上午 → 午休 → 下午 → 16:18 → 17:00 → 离开办公室。镜头始终在同一间办公室里，产品界面就是他桌上那部手机和那台显示器上的屏幕。镜头推近屏幕就得到界面特写，不插入独立的产品图。

## 创作要点

- **因果和动作衔接**：每个产品点都由人物的动作引出：他看手机、他吃饭、他犯困去点鼠标、手机振动他低头看、倒计时归零他站起来。镜头推近只是跟着他的视线，没有凭空插入的产品图。
- **哪块屏幕在什么时候出现**：上午和午休，支架上的手机开着 DoneAt 计时页（B 版是先看到只有时间的锁屏，再解锁进 App）。16:18 起手机已锁屏，只有推送。实时活动只在 16:45 之后出现，对应 App 默认的下班前 15 分钟（可选 5、15、30 分钟）。
- **功能介绍**：故事结束后，用 8.5 秒介绍专注、记录和人生视图三个 Plus 功能。专注和记录热力图用的是 `../../ios/raw/` 下的 3.2.0 真实截图，只在截图上叠了会动的番茄钟数字和汇总卡片；人生视图的卡片按 `LifeView.swift` 的结构和真实文案重画。收入数字是示意值（月薪 12,000，年薪 144,000，和宣传图同一套）。
- **时间只在该走的时候走**：快进只出现在没有倒计时读数的全景里，挂钟、光线和打字一起加速，表现的是时间流逝。画面上一旦出现倒计时读数，就严格按真实时间走。午休那段是唯一例外：锁屏时钟快进，倒计时停着不动，这正是要展示的暂停功能。不暗示 App 能让时间变快。
- **一致的数字**：班次 09:00–17:00，午休 12:00–13:00，有效工时 7 小时。10:27 → 20%，12:00 → 42%，15:10 → 73%，16:18 → 90%（对应真实的「今天还剩 10%」里程碑），17:00 → 100%。App 计时页、锁屏实时活动、木鱼浮窗都由同一个时间模型算出。
- **人物动作**：起身按真实顺序做：先把脚收回到膝盖下方，上身前倾、手撑桌沿，臀部抬起并前移，上身再立直，椅子随之滑开。膝盖在坐姿和站姿下都朝前弯。走路是完整的步态循环：支撑脚踩实不动，摆动脚抬起迈到前方，臀部有起伏，拿包的手轻摆，另一只手和腿交替摆动。 脖子不属于头部图层，每一帧从领口内一直连到下颌，头部抬、低、转时都和身体连着。
- **一个视觉世界**：人物、办公室和设备都是同一套 SVG 插画，分远、中、近三层，镜头推拉时有视差；光线和色调随一天的时间从清冷的上午过渡到温暖的傍晚，再到下班后的暮色；全片叠加胶片颗粒和暗角。
- **字幕**：进场只用 0.22 秒淡入加上移，不用长时间的模糊动画。首句在第 0 帧就完整可见。每段最多一句标题加一句短副标题，画面承担主要叙事。
- **声音**：
  - 有房间底噪；只在人物打字的时段才有打字声。
  - 手机振动比画面早一拍响起，把镜头从全景引到手机上。
  - 木鱼声照搬 `components/MiniCountdown.tsx` 的合成参数。
  - 倒数的「哔」和画面上数字跳变同一帧。
  - 配乐在各版开头故事落定后才进来（A 版 0.3 秒、B 版 4.1 秒、C 版 1.5 秒）；在最后几秒只剩铺底，归零时落到大和弦并保持约 2 秒，之后按 F–G–Am–G 继续走（配轻鼓），陪着起身、离开和功能介绍，到 CTA 回到 C 再淡出。

## 安全区

主信息都在 x=64–920、y=190–1500 的编辑区内，顶部 150 像素、右侧按钮列（x ≥ 920，y 700–1560）和底部 380 像素不放关键信息。检查的是带 `--safe` 叠层的截帧，以及缩到 390 像素宽的手机尺寸预览。这是本片自定的保守范围，不是 TikTok 官方统一的像素模板；投放前请用对应广告形式的预览再复核一次。

## 生成

需要本机 Google Chrome、ffmpeg 和 Node 22 以上，不新增 npm 依赖。

```sh
node scripts/marketing-shots/promo-video/tiktok-v3/render.mjs --variant progress
node scripts/marketing-shots/promo-video/tiktok-v3/render.mjs --variant glance
node scripts/marketing-shots/promo-video/tiktok-v3/render.mjs --variant woodfish
```

每版约 2 分半。成品在 `out/<variant>/`：

- `doneat-<variant>-zh-60fps-music.mp4`：音效 + 合成配乐；
- `doneat-<variant>-zh-60fps.mp4`：纯音效版，方便换平台音乐。

`--stills 0,2.4` 只输出指定时间的 PNG，加 `--safe` 叠加安全区。浏览器里打开 `scene.html?variant=glance&t=2.4` 可以查看单帧，`&play` 实时播放。

- 时间轴在 `scene.html` 的 `B`（共用正片）、`HOOK_CAM`/`HOOK_POSES`（开头镜头和动作）、`BODY_CAM`/`BODY_POSES`（正片镜头和动作）；
- 字幕在 `HOOKS` 和各个 `.cap` 元素；
- 声音事件在 `cues()`，改完会自动带进 `audio.mjs`。

## 测试建议

三版的正片、CTA、时长和音乐完全相同，只有前 6 秒不同。比较时：
- 看 3 秒和 6 秒的留存率，以及完播率、主页点击和搜索或下载转化；
- 如果用纯音效版另配平台音乐，三版必须用同一首歌、同样的音量；
- 先定开头，再单独测试配乐或文案。

## 已知取舍

- 人物是插画，不是真人，表演靠关节动画完成。如果要换成真人实拍或生成视频素材，镜头表和时间轴可以直接当拍摄脚本用。
- 没有口播。
- 配乐是代码合成的，质感不如正式曲库，建议正式投放用纯音效版配平台音乐。
- 原版（`../scene.html`、`../render.mjs`、`../audio.mjs`、`../out/`）和 `../tiktok-v2/` 都没有改动，只复用了原版的图标、滚动数字、计时页界面和礼花物理参数。

- **日期**：2026-09-04
- **范围**：iOS / iPadOS 原生 SwiftUI 的专注页、番茄钟计划页、快捷添加 sheet、计时页「接下来」时间线上的番茄钟行，以及这些界面涉及的 19 个 UI locale
- **依赖**：[011](011-ios-records-focus-release-remediation.md) 已修的番茄钟行为、[013](013-records-day-canvas-and-visual-language.md) 的画布方法论与视觉语法、[006](006-free-trial-subscription.md) 的 Plus 权益模型
- **目标**：把番茄钟从「两个功能目录页 + 一张够不着的表单」重排成一张画布；让**现在 / 今天 / 常用**三个尺度各自先回答一个用户问题；把「创建任务」和「把它放进某一格」合并成同一个动作

## 为什么另开 014

011 第十节写得很清楚：真机那一轮修的是**行为**，判定要重做的是**排布**。用户点名的三处是「快捷创建任务、一天的排布、常用天数」，恰好对应现在的三个文件：`FocusAddTaskSheet`、`FocusPlanningView` 的格子网格、`FocusPlanningView` 底部的模板区。

这件事在代码和测试里看不见，所以值得写下来：`AppTests` 的 `FocusStoreTests`（30 项）与 `FocusPlannerTests`（18 项）全绿，覆盖的都是模型层，没有一项描述「用户要点几下才能把一个任务放进某一格」。功能是对的，路径是乱的。

013 的经验是这次的方法：记录页之所以能收口，是因为**先定下「每个尺度先回答一个用户问题」这条原则，再动控件**，而不是先挪控件。本计划照做，所以第一节是现状地图，第二节是原则，第三节以后才是重排。

## 与 010 / 011 / 013 的优先级

发生冲突时，014 只在以下范围优先：

1. 010「专注入口迁移」一节里那个「计时页左上角 + → 添加待办」的形态。它当时没有落地成按钮（见 F1），本计划重新决定它的位置与内容。
2. 010 信息架构图中「计时 Tab └ 左上角 +」那一支。
3. 专注页与计划页作为两个独立页面的划分。

不优先、不重开的：011 修过的全部行为契约与它仍在进行的真机验收对象；013 的记录日画布与视觉语法；006 的权益矩阵。**011 的番茄钟行为验收在进行中，本计划实现前必须确认它已签收**——否则验收对象会在验收过程中变形，这正是 011 第十节要求「重排单独立项」的原因。

## 一、现状：番茄钟今天散在哪里

### 1. 六个露头的地方

| --- | --- | --- | --- | --- |

| 2 | 计时页「接下来」时间线 | `TimerDesignView.swift:266`、`TimerStatusViews.swift:87 / 218` | **今天已排好的番茄钟格与休息格**，和午休、下班混排 | 否，纯只读 |
| 3 | 专注页 | `FocusDesignView.swift` | 新建表单 / 运行中卡 / 下一步 / 通知故障 / 常用任务 / 去计划 / 今天任务列表 / 放不下提示 | 是 |

### 2. 点击路径深度

| 用户想做的事 | 现在的路径 | 层数 |
| --- | --- | --- |
| 开始一个已存在的任务 | 计时根 → 专注页 → Start | 2 |
| 新建一个任务 | 计时根 → 专注页 → 标题 → 图标 → Stepper → 添加 | 2 + 一张表单 |
| 把某个任务放进某一格 | 计时根 → 专注页 → 计划今天 → 点格子 → 选任务 | 4 |
| 上一条但任务还不存在 | 走到第 4 层才看到「先去专注页添加任务」，退回两层，再走一遍 | 4 + 回退 |
| 存一个「常用的一天」 | 计时根 → 专注页 → 计划今天 → 滚到网格底部 → 保存为模板 → 命名 alert | 4 + 滚动 |
| 改 25 / 5 / 15 时长 | 专注页 → 齿轮 → sheet（且常被锁住，见 F5） | 2 |

### 3. 每屏现在回答几个问题

- **专注页**：八个。新建什么任务（表单）、现在跑到哪（运行卡）、这一格完了干嘛（下一步卡）、通知是不是坏了（故障卡）、我常用的任务（横向 chips）、去哪儿排（跳转行）、今天有哪些任务（列表）、哪些放不下（尾部提示）。八张卡按加载顺序竖排，没有主结论。
- **计划页**：两个，而且不同尺度。「这个班次的格子怎么排」（今天）和「我的常用一天长什么样」（模板，跨天）被叠在同一次滚动里，模板在网格下面。
- **计时页「接下来」**：回答了「今天怎么排」，但在一个不能编辑的地方回答。

对照 013 的标准——每个尺度先回答一个问题、主结论只有一处——番茄钟目前一条都不满足。

### 4. 现状里的结构性问题

这些不是视觉问题，是排布和契约问题；重排必须把它们一起收掉，否则新画布会继承同一批毛病。

- **F1 `FocusAddTaskSheet` 根本够不着。** 全仓只有 `TimerDesignView.swift:65` 通过 `store.presentAddFocus` 展示它，而写这个标志位的 `beginAddFocus()`（`OffWorkStore.swift:4781`）**没有任何调用者**。010 说好的「计时页左上角 +」从没接上，顶栏最后放的是通往整页的 `timer` 圆钮。于是仓库里存在两套互相残缺的建任务界面：专注页的卡有估算 Stepper 但不能「立即开始 / 安排时段」，够不着的 sheet 能「立即开始 / 安排时段」但把估算写死成 1。
- **F2 「今天的任务」有两个定义。** `focusTasksForFocusPage`（`OffWorkStore.swift:5431`，今天 + 未来 + 今天已完成）用于专注页列表；`focusTasksForToday`（`:5419`，仅今天且未完成）用于计划页的指派 sheet 和 overflow。结果：排给明天的任务在专注页看得见，在计划里选不到。
- **F3 「常用任务」chip 的效果不在原地。** 点一下走 `applyFavoriteFocusTask`，它**复制**出一个今天的新任务（`:5484`），既不开始也不高亮，用户看到的变化是屏幕下方列表多了一行。排序按 `editedAt`，会因为无关编辑而漂移。
- **F4 「常用天数」是第三个尺度，却挂在第二个尺度的尾巴上。** 模板区在计划页网格下方；「保存为模板」是一个带输入框的 alert。
- **F5 存一个模板会静默冻结番茄钟时长。** `updateFocusTimerSettings` 在 `templates` 非空时直接 `return false`（`OffWorkStore.swift:4125`），而设置 sheet 的锁定条件是「有已保存的计划」（`FocusDesignView.swift:728`）。有模板但当天还没有计划时，输入框可编辑、保存按钮可点、`save()` 忽略返回值直接 `dismiss()`——用户改完发现什么也没变，且没有任何解释。
- **F6 格子的起始时间会在一天中漂移。** `focusWorkBlocks()` 每次用 `.now` 重算，而 `focusMicroBreakBoundaries` 只保留**晚于当前时刻**的微休息边界；开启微休息的用户，上午算出的切点到下午会消失，后续格子的 `startAtMs` 随之改变，而计划指派正是以 `blockStartAtMs` 为键。默认关闭微休息时不触发，一旦开启就会出现「排好的格子对不上了」。
- **F7 免费用户的路径是一串静默空操作，不是一次诚实的付费页。** iPhone 顶栏是裸 `NavigationLink`，不过门；iPad 走 `openPaidOrRun`，先弹付费页。免费用户在 iPhone 上能进专注页、能进计划页、能点开格子、能选任务，而 `assignFocusBlock`（`:4148`）在 `plus.isAuthorized` 为假时直接 `return`，什么也不发生、什么也不说。`clearFocusBlock` 甚至没有这道 guard。
- **F8 未订阅时选择的时段会被丢掉。** `addScheduledFocusTask`（`:4622`）在未授权分支把 pending action 降级成不带 `scheduledStartAt` 的 `addFocusTask`，购买回流后任务变成没有时段的普通任务。
- **F9 自动休息格是一个会给正反馈的死按钮。** `focusAssignment(for:)`（`:4133`）为 `.breakTime` 格**合成**一条指派，所以计划页把自动休息格也渲染成可点按钮；但 `assignFocusBlock` 与 `assignFocusBreak` 都 guard `block.kind == .task`，选任务或选休息都会静默返回，而 sheet 仍然触发一次 selection 触感并关闭。更糟的是那张 sheet 上的「清空这一格」对休息格会执行 `clearFocusBlock`：它匹配不到任何指派，却仍然把 `appliedTemplateID` 置空并写盘——用户以为什么都没发生，今天的计划已经从模板上摘下来了。

## 二、已定产品原则

1. **番茄钟有三个尺度：现在、今天、常用。每个尺度先回答一个问题。**
   - 现在：「我这一格在做什么，还剩多久，结束后干嘛？」
   - 今天：「这个班次装不装得下我想做的事？装在哪？」
   - 常用：「我平常的一天长什么样？」
   与 013 的写法保持一致：每个尺度只有**一处**允许明显强调，其余是解释。
2. **番茄钟的原子是「一格时间」，不是「一个任务」。** 今天的画布画的是班次里的格子；任务是填进格子的内容。
3. **同一件事只有一处可编辑，而且就在能读到它的地方。** 今天的排布已经画在计时页「接下来」上；重排后从那里可以直接进入并选中对应的格子。
4. **创建任务和安放任务是同一个动作。** 空格子上的「新建并放在这里」必须存在，否则第 4 层的死胡同（F2 + 「先去专注页添加任务」）会原样留下。
5. **常用是一个尺度，不是某一屏的尾巴。**
6. **行为不改。** 011 修过的循环、边界、跨夜、双设备、模板幂等、**估算语义**与 overflow 口径全部保持；`FocusStoreTests` 与 `FocusPlannerTests` 必须**不改断言**地继续通过。本计划新增的测试只描述新的排布契约。
7. **规则不进 Swift。** 格子继续由 `FocusPlanner` 从共享规则给出的有效 `segments` 推导；微休息边界继续来自 `lib/reminders.ts` 的桥接结果。
8. **不新增持久化。** 全部落在既有的 `focusPlanningConfiguration` 与番茄钟任务 / 会话上。
9. **锁定先说明，再销售。** 免费用户看到的是一处诚实的付费入口和一句解释，不是一串点了没反应的控件。
10. **没有静默空操作。** F5、F7、F9 是同一种病：控件看起来能用、点下去有反馈、什么也没发生。新画布里任何点得动的东西都必须产生可见结果或说明为什么不能。

## 四、现在（画布顶部固定带）

一处结论，三种状态，永远只显示其中一种：

- **运行中**：任务标题（不是再写一遍「专注」）、剩余时间、结束时刻、停止。沿用现有 `activeCard` 的内容与「停止不用主按钮样式」的判断。
- **刚结束一格**：`focusLastNextAction` 给出的唯一下一步（短休 / 长休 / 下一个专注）+ 跳过。
- **空闲**：当前工作格有任务时显示「开始」，只使用该格剩余时间；空格提供「添加并开始」。未来格仅用于安排，不能通过此处提前启动。没有当前工作格时展示下一格信息和添加入口。

通知故障显示为运行卡中的次要状态入口，点开后说明权限状态并提供系统设置或重试；它不能挤压计时和停止操作。

## 五、今天：按真实时间比例的班次时间带（分叉 1 已定）

### 几何

- **纵向、可滚动、带整点刻度尺**，就是日历应用的那套隐喻，不发明新的。
- 覆盖范围是**这个班次**，不是自然日：从首个 segment 起到末个 segment 止；有加班时延伸到加班终点。跨夜班保持一条连续的带，刻度标签越过 24:00 继续走次日的小时——「今天」这个尺度问的是「这个班次」，不是 civil day，这一点与 013 的日画布故意不同，要在两处文案里写清楚。
- **密度由配置的专注时长反推**：`pointsPerHour = max(96, 44 * 60 / focusMinutes)`。专注时长可配 10–60 分钟，这个式子保证一个专注格永远不低于 44pt 命中区；96 的下限是给 60 分钟格时的刻度尺留可读性。25 分钟 → 约 106 pt/h，8 小时班次约 850pt，正常滚动。
- **严格按比例，不给短块设最小高度。** 5 分钟短休在 106 pt/h 下是 9pt，1 分钟短休是 1.8pt——它就该看起来像一条发丝线，因为它就是一分钟。休息块的**文字标签只在渲染高度 ≥ 20pt 时出现**，低于此只画分隔线；VoiceOver 无论多短都完整播报「休息 5 分钟」。这是「按真实时间比例」这个决定的直接代价，写在这里以免以后被当成 bug 修成等高块。
- 午休与班次间隙渲染成不可编辑的凹陷区，整段只标一次。
- 现在线沿用 013 日画布的处理。

### 状态与可编辑性

| 格子 | 外观 | 可点 |
| --- | --- | --- |
| 未来 · 空工作格 | 凹陷 + 虚线 + 前缘「+」 | 是 → 指派 sheet |
| 未来 · 已排工作格 | 任务图标 + 标题 + 分类色 | 是 → 改 / 清空 |
| 未来 · 自动休息格 | 细凹陷条，无命中区 | **否**（见下） |
| 现在所在格 | 强调描边 + 现在线 | 同上 |
| 已过格 | 去饱和、降透明 | 否（沿用现有 `isElapsed`） |

**自动休息格改为不可点，是 F9 的设计解法而不是补丁。** 底层两个写入方法本来就 guard `block.kind == .task`，也就是说自动休息格从来不可写；现状只是把一个永远不会生效的按钮画了出来，还给它配了触感。要休息，走「把一个工作格设为休息」（`assignFocusBreak`，作用在 `.task` 格上），这条路径保留在格子 sheet 里。

### 时间带下方

- 今天的任务列表：图标、标题、**完成 n / 已排 m**、以及未排任何格子时的「未安排」状态。
- 「放不下的」（`focusOverflow()`）作为该列表的**脚注**，不再是独立卡片。它的算法一行不改。
- **进度改用「已排」而不是「估算」，是为了不动行为。** 格子优先会让「排了 2 格却显示 0 / 1」这种矛盾冒出来，最直接的修法是让指派抬高手动任务的估算——但 `templateAndManualTaskEstimatesRemainSemanticallyDistinct` 明确断言手动任务排进两格后估算仍是 1，而 011 的真机验收还没签收，不能在验收期间改它的断言。用「已排 m」表达当前排布、把 `estimatedPomodoros` 留给用户意图和 overflow，两个概念各自诚实，且零行为改动。
- 修 F2：指派 sheet 与任务列表用**同一个**任务查询。
- 修 F6：`extraBoundaries` 整个去掉，见第十四节。微休息不再切割格子网格，`blockStartAtMs` 因此在一天内稳定。这是本计划触及规则**消费方式**的改动（规则本身不动），需要一条新测试锁住。

### 不在班次里的时候

现状是 `focusWorkBlocks` 返回空、计划页给一张空状态卡。新画布改为：**没有进行中的班次时，时间带画下一个班次**，并在带顶标明是哪一天的班次。理由是「今天」这个尺度的问题在下班后依然成立，而且用户排明天的活儿正是在下班后。休息日且无下一班次时才回到空状态。

### 无障碍与自适应

- **辅助功能字号（`.accessibility1` 及以上）整条尺度降级为按时间排序的列表**，行内容为「时间 · 状态 · 任务」，动作与带上完全相同。013 已经确立了大字号下降级为列表这一模式，这里沿用。
- Reduce Motion：切换尺度与选中格子改交叉淡化，时间带不做重排动画。
- Reduce Transparency：锁定层改实色。
- iPad 与横屏：时间带按内容测量宽度封顶（与其他内容一致的 680pt 上限），不横向拉伸。

## 六、常用（分叉 2 已定）

### 常用任务：点一下 = 放进下一个空格

- 动作定义：由该常用任务生成今天的任务（沿用 `applyFavoriteFocusTask`），并指派到**第一个开始时刻晚于现在、且尚无指派的工作格**。一次动作、一次触感、一个可撤销单元。
- **反馈必须在变化发生的地方**：执行后切到「今天」尺度，滚动到该格并选中它。这是 F3 的解法——现状的问题不是复制本身，而是效果出现在屏幕别处。
- 没有空格时**不静默**：说「这个班次没有空格了」，并提供「仍然加到今天」（创建为未安排任务，随后在列表里以「未安排」出现）。
- 没有班次时：说明原因是「今天没有班次」，动作降级为同一个「加到今天」。
- 排序改为稳定顺序（`sortIndex` / 创建序），不再用 `editedAt`（F3 后半）。
- chip 的无障碍提示要说出落点（「放进 14:00 的空格」），而不是只念任务名。

### 常用的一天

- 现在的模板搬到这里：应用、设为默认、删除，以及「把今天存成常用的一天」——从带输入框的 alert 改成正式 sheet，保存前能看见将要存下的排布。
- 修 F5：设置 sheet 的锁定条件与 `updateFocusTimerSettings` 的 guard 对齐（有任何模板即锁），锁定原因写成能读懂的一句话，`save()` 必须检查返回值而不是静默 dismiss。
- 与小组件对齐：`WidgetSnapshotPublisher` 的「接下来」应投影**今天真实的计划**（`focusPlanAssignments`），而不是只投影默认模板槽位，否则应用内与桌面上是两个答案。

## 七、创建路径：格子优先（分叉 3 已定）

主路径是格子，任务列表降级为解释：

1. **点空格 → sheet**：选今天已有的任务 · **新建并放这里**（标题 + 图标）· 设为休息。新建时一次写入任务与指派。这是最常用的一条，两层。
2. **工具栏 +（次路径）**：创建 sheet 首先显示标题、落点和提交；图标、估算、常用标记收进「更多」。工具栏默认安排进空格，顶部「添加并开始」默认立即开始；两种落点都保留估算。这正是 F1 的收口——把够不着的 `FocusAddTaskSheet`（能选落点、估算写死 1）和专注页的卡（有估算、不能选落点）合成一张完整的表。
3. 旧的 `newTaskCard` 消失。它原本占着空闲时页面顶部的位置，那个位置现在归「现在」带的「下一格 + 开始」。

估算 Stepper 只出现在次路径，因为主路径的估算由用户放了几格自然表达；两条路径都不改 `estimatedPomodoros` 的语义（见第五节）。

## 十三、「常用的一天」需要自己的画布

第六节把模板搬进了「常用」尺度，但没有回答一个更早的问题：**在一天已经过了一半的时候，怎么排出完整的一天。**

代码事实，三条，合起来才看得清：

- `FocusPlanner.workBlocks` 返回的是**整个班次**的格子，不随 `now` 截断。所以下午存模板时，上午的格子是在场的。
- 但 `saveFocusTemplate` 只收下**有指派**的工作格（没有指派的 `return nil` 丢掉），而计划页对已过的格子是 `.disabled(isElapsed)`。所以下午存下来的模板，上午永远是空的——不是存不下，是**排不上**。
- 反过来，`applyFocusTemplate` **不跳过**已过的格子：它会照着 `blockIndex` 把上午一起写上。

于是系统里存在一条不对称：**模板能写上午，人不能排上午。** 用户问的正是这条缝。

决定：

- 「常用的一天」有自己的编辑画布，画的是**用户配置的标准班次**（`startMinutes`–`endMinutes` 加午休设置），不是今天的实际班次。没有现在线、没有已过态、没有加班延伸，从第一格排到最后一格。模板本来就是跨天的东西，用「今天」当模具才是问题的来源。
- 「把今天存成常用的一天」保留，但改成这个编辑器的**预填入口**：把今天已排的部分带进去，停在编辑器里，让用户补齐上午，看过完整的一天再保存。它不再是一个存完就结束的动作。
- 允许留空。模板里的空格子应用后就是空格子。但保存前要说清楚「上午 5 格是空的」，不能让用户以为存了一整天。
- 班次形状会变。模板按 `blockIndex` 映射，班次变短时尾部槽位会被丢掉。编辑器顶部标明这条模板是按哪种班次排的（「按 09:00–17:00 · 12 格」），应用到更短的班次时说明丢了几格。
- 这里也是解释 F5 最自然的地方：存过模板之后番茄钟时长会锁住，因为槽位是按当前节奏编号的。

## 十四、番茄钟的休息接管健康提醒

健康提醒（微休息）和番茄钟的休息确实打架，而且不止是「两个通知」那么轻。

- 微休息由 `lib/reminders.ts` 生成，默认 60 分钟一次，`microBreakEnabled` 默认关闭。番茄钟默认 25 分钟一轮。两者都在说「该休息了」，节奏不同。
- 更要紧的是**微休息会改番茄钟的几何**：`focusMicroBreakBoundaries` 把微休息时刻当作硬切点喂给 `workBlocks`，开启微休息等于重新切割格子网格，切点前放不下一整格的地方直接浪费，而且切点集合随 `now` 变化——这正是 F6。
- 番茄钟自己**只在跑着的时候说话**：`scheduleFocusTimerNotification` 只为当前 session 的结束排一条通知。没按开始就一条提醒也没有。
- 这条线代码里早就留好了。计时页「接下来」那条微休息行的注释写着：这是番茄钟以后要接上的接缝。

决定：

- 这个班次**有番茄钟计划**时，微休息交给番茄钟：不再按固定间隔排微休息通知，改为在计划里的**长休息**开始时提醒。长休息默认每 4 轮一次（25×4 加 3 次短休 ≈ 115 分钟），与 60 分钟的微休息量级接近，不会把提醒数翻三倍。短休息不单独发通知——跑着的时候 session 结束通知已经在说这件事，没跑的时候用户本来就不在这套节奏里。
- 同时**去掉 `extraBoundaries`**。番茄钟接管休息之后，没有第二个「该休息了」需要避让，微休息就不该再切割格子网格。这从根上消掉 F6，比继续修那个 `> now` 的过滤条件干净。第五节原本写的 F6 修法作废，以本节为准。
- 通知是提前排好的，所以接管必须**重排**：用户在 14:00 才建立计划时，当天剩下的微休息通知早在班次开始时就排进系统了。按 `microBreak:<segmentStart>:<bucket>` 这个稳定 id 撤掉，计划被清空时再排回来。
- 设置里的健康提醒一行保留，被接管时显示状态和原因，并给一条通往番茄钟的路径。文案不写「已停用」——它没有被关掉，是换了节奏。
- 没有番茄钟计划的班次、以及免费用户，微休息完全照旧。这是加一条接管规则，不是替换健康提醒。
- 这是一处必须明说的行为改动，需要新测试锁住两件事：开启微休息不再改变格子起点；有计划的班次不再排固定间隔的微休息通知，而是在长休息处排。

## 十五、实时活动与灵动岛

同样需要重画，而且这里有一个比样式更靠前的问题。

- **一次只有一个活动。** `LiveActivityReconciler` 保证这一点：开始专注会**结束下班倒计时活动**，换成专注活动。所以专注期间，用户看不到「还有多久下班」。
- 专注活动和下班活动**共用同一套视图**，只有 `timerLabel`（阶段名）和 `destination` 不同。灵动岛的 compact 与 minimal 都是品牌标记，两种活动在岛上长得一模一样。
- payload 里**没有任务名，也没有任务图标**。`timerLabel` 是阶段标签（「专注中」），不是「需求梳理」。

所以要解决的是四件事：岛上分不出是哪种活动、不说在专注什么、不说下一步、以及专注把班次倒计时挤掉了——而在新画布里，格子本来就是装在班次里的，这两个尺度不该二选一。

决定：

- `ContentState` 增加三个可选字段：`taskTitle`、`taskIcon`（SF Symbol 名）、`nextLabel`。沿用现有「可选字段让旧活动仍可解码」的做法。**不加任何薪资相关字段**，App Group 的 salary-free 边界不动。
- 灵动岛：
  - **minimal** —— 专注时换成任务图标，不再是品牌标记。这是唯一能用一个字形区分两种活动的位置。
  - **compactLeading** 任务图标，**compactTrailing** 这一格的倒计时。
  - **expanded** —— leading 是图标加**任务名**（不是「专注中」），trailing 是这一格的结束时刻，bottom 是倒计时条加一行「14:25 结束 · 之后长休息 15 分钟」。
- 休息中图标换 `cup.and.saucer.fill`，keyline 走 `recordsBreak` 的 teal，标题区分短休 / 长休，下一步写「开始下一轮专注」。下一步由会话阶段决定，不能从之后的计划格猜测，否则长休期间会再次提示长休。
- 锁屏卡片上半是任务加倒计时，下半显示共享规则给出的**下班时刻**。2026-09-05 回归发现，写进 payload 的「班次剩余」字符串会在后台冻结，因此改为 `shiftEndAtMs` + 本地化标签；不在扩展里复制跨午休的有效时间计算。旧 `shiftRemainingLabel` 仅保留解码兼容，不再显示。
- 专注 / 休息进度条使用 `ProgressView(timerInterval:)`，由系统插值；expanded 阶段说明替代会冻结的百分比。普通下班活动仍按完整有效 segments 计算进度，不落入只取第一段的专注分支。
- 颜色：`keylineTint` 现在写死 `activityOrange`，改成随 surface 走——专注 indigo、休息 teal、下班倒计时橙。岛上一抹颜色就能区分三种状态，这也和第九节「橙色不是一种时间」一致。

## 十六、已拍板与仍待定

2026-09-04 由用户拍板：

1. **今天用按真实时间比例的时间带**（第五节）。代价已写明：短休息在带上是发丝线、大字号必须降级为列表、密度随专注时长变化。
2. **常用任务点一下 = 放进下一个空格**（第六节）。
3. **格子优先**（第七节）。任务列表降级为解释；估算不因此改变语义。

2026-09-04 第二轮确认的三处（第十三至十五节）：常用的一天需要自己的编辑画布；番茄钟的休息接管健康提醒并连带去掉 `extraBoundaries`；实时活动与灵动岛按专注 / 休息 / 下班三种状态重画。

由这些决定新产生、但不阻塞开工的小问题：

- 时间带在「下一个班次」模式下是否显示日期头，还是靠刻度尺自明——实现阶段 2 看真机再定。
- 「放进下一个空格」是否需要 undo（摇一摇撤销 / 顶部一行「已放到 14:00 · 撤销」）。倾向后者，成本低且与反馈落点一致。
- 未安排任务在列表里的排序位置：与已排任务混排按时间，还是单独一段。倾向单独一段，避免它们伪装成有时间的东西。
- 接管后是否允许用户单独把微休息调回固定间隔。倾向不给这个开关：两套「该休息了」同时开着，正是这次要收掉的东西。
- 模板编辑器要不要允许改班次形状（比如为「会议多的一天」排一个更短的班次）。倾向不允许——模板是排布，不是排班。
- 锁屏卡片下半那行班次剩余，在加班时说什么。加班没有计划终点，可能要退成「加班中」。

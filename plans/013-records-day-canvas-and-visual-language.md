# 013 — 记录日画布、视觉语法与单一结论

- **状态**：TODO — 产品口径已定，尚未实现
- **日期**：2026-09-01
- **范围**：iOS / iPadOS 原生 SwiftUI 的记录主画布、周日列与月格视觉语法、日期详情、人生总结、Plus 锁定文案与 19 个 UI locale
- **依赖**：[010](010-records-ui-iteration.md) 的单画布与记录 IA、[011](011-ios-records-focus-release-remediation.md) 的发布阻断修复、[006](006-free-trial-subscription.md) 的权益模型
- **目标**：让“日”成为记录体验的可读原子；用一套稳定的颜色、纹理和文案区分事实、推算、修正与锁定；让日、月、年、人生每个层级先回答一个用户问题，再提供数据解释
- **不包含**：删除周视图、把日加入顶部五段选择器、连续变形式缩放、Web / Desktop 记录页、HealthKit、薪资规则、记录持久化或 CloudKit schema 变更

## 为什么另开 013

010 已经完成记录页最重要的结构性重构：默认月历、周 / 月 / 年 / 人生单画布、图在上总结在下、年与人生沉浸展开，以及事实与推演分离。011 又补齐了日期索引、免费遮蔽、时区、导入导出、冲突与真机前的模拟器验收。

当前剩下的主要问题不是再增加一个图表，而是表达仍有三处不够统一：

1. 月历点中一天后只出现指标卡，缺少能解释“这一天具体发生了什么”的完整时间画布；“日是记录原子”只存在于数据模型，没有成为用户能阅读的界面。
2. DoneAt 橙色同时承担选择、今天、记录、计划、修正和活动标记，交互状态与数据类别在小月格里容易混成一种意思。
3. 周 / 月 / 年使用四项总结，人生没有同等级的时间分配结论；日期详情又把多个指标平铺，用户需要自己从数字里寻找重点。

本计划只收口上述呈现层问题。它不推翻 010 / 011 的数据、权益、同步和导航基础，也不以新视觉稿为理由重开已经通过的发布阻断项。

## 与 010 / 011 的优先级

发生冲突时，013 只在以下范围优先：

1. 周 / 月选中日期后的常驻详情改为紧凑摘要，并提供“看这一天”进入完整日画布。
2. “全部记录 → 日期”与“周 / 月 → 看这一天”复用同一个日画布。
3. 日期编辑的主要入口移动到日画布；编辑本身继续使用现有系统 sheet、Plus 权益和未保存退出确认。
4. 月格不再用品牌橙填充来表示工时；品牌橙主要表示交互，工时使用数据分类色与结构。
5. 人生尺度增加一个明确标为推算的时间分配结论。
6. Plus 锁定文案明确说明记录仍在本机继续保存，且不改变免费 7 日窗口。
7. 周日列不再用整条换色表示“这天有加班”，改为与月格、年展开条相同的分段。

以下 010 / 011 口径继续有效：

- 顶部仍是周 / 月 / 年 / 人生四档，默认月；不增加放不下的第五段。
- 周、月免费但只揭示记录时区内 `[今天 - 6 天, 今天]`；年、人生和记录页编辑需要 Plus。
- 锁定视图模型、View 树、VoiceOver、日志和截图都不得携带锁后真实值。
- 年视图收起为节奏 / 密度画布，展开自动切成 12 条共享刻度的月度比较条。
- 人生视图只到退休，不猜寿命，不把推演写成真实记录。
- 完整导入、导出、删除与冲突处理继续是数据权利。

## 已定产品原则

1. **日是内容原子，不是第五个顶部分段。** 日画布是记录层级的详情目的地；月和周负责比较，日负责解释。
2. **每个尺度先回答一个问题。** 日回答“这一天还剩多少时间真正属于自己”，月回答“这个月哪些天最重”，年回答“哪些月份最重”，人生回答“按当前设置，到退休前的时间大致如何分配”。日的问题是余额而不是分配：时间带和分类列表回答“去了哪里”，但那是解释，主结论只有“属于你的清醒时间”一个。两处写法必须一致，否则日画布会被实现成第二张分配表。
3. **一个事实只用一种语言。** 正常工作、加班、班中休息、睡眠、自主时间和无法分类在日时间带、月格小柱、年展开条与占比条中复用同一分类 token。
4. **交互色与数据色分工。** DoneAt 橙色用于选择、今天、按钮、链接和强调；数据类别颜色只出现在图表。加班即使继续使用系统橙，也必须靠“柱尾分段 + 标签 / 纹理”成为第二通道，不能要求用户分辨两种相近橙色。
5. **来源比精度更重要。** 已记录、用户修正、按排班推算、按人生设置推算、计划、未记录和锁定都要有可读文案；纹理和标记只是文案的视觉缩写。
6. **推算永不落库。** 日画布和人生总结可以读取内存投影，但不得为视觉连续性创建 DayOverride、DailyWorkSummary、观察、CloudKit 记录或缓存事实。
7. **当前计算口径不因文案重写。** `segments`、午休 gap、加班、跨夜和 DST 继续由共享 TypeScript 规则与现有聚合模型决定；Swift 只组织输入和渲染结果。
8. **锁定先安抚，再销售。** 文案先说明记录仍在本机继续保存，再提供中性的“查看方案”；不能让用户以为未购买期间数据会丢失或上传。
9. **缩放仍是增强手势。** 当前分档缩放保留；本轮不做跨尺度连续形变、投影吸附或复杂手势物理。
10. **不新增行为分析。** 本轮通过真机任务走查判断日画布价值，不为比较“日与周谁更常用”新增个人行为历史或新的远端分析数据。

## 视觉克制基线

三端通用的克制基线已经写进 `AGENTS.md` 的 `UI rules` 开头：默认收敛、尺寸与间距按判断而非规格、辅助入口不进视觉中心、常见功能用大众图标隐喻、层级优先用轻手段表达、实现后与同屏元素对比再收敛。本计划全部遵守，不在这里重写一遍；下面只写记录页特有的落法。

- **本页的辅助层是**：尺度选择器、全部记录入口、展开 / 收起、月份选择、人生阶段图例、来源标签、信息按钮和睡眠来源说明。它们不与月历、时间带或主结论争注意力。
- **每个尺度只有主结论一处允许明显强调**，且靠独占位置和字号层级实现，不靠色块、渐变或阴影。日的主结论是“属于你的清醒时间”，时间带和分类列表是解释，不是第二个结论。
- 分类色、锁定层和纹理的具体边界见「月格视觉语法 → 颜色边界」与「Plus 锁定体验与文案」，不在本节重复。

## 信息架构与导航

```text
记录 Tab
├── 周 / 月 / 年 / 人生（保持四档）
├── 周 / 月
│   ├── 点选日期 → 图下紧凑摘要
│   └── 看这一天 → push 日画布
├── 全部记录
│   └── 年 → 月 → 日期 → push 同一个日画布
├── 日画布
│   ├── 24 小时时间带
│   ├── 单一主结论 + 分类解释
│   └── 编辑这一天 → 系统 sheet
└── 年 / 人生
    └── 保持现有收起 / 沉浸展开
```

### 导航语义

| 入口 / 目的地 | 呈现 | 返回行为 |
| --- | --- | --- |
| 周 / 月点选日期 | 同页状态更新 | 不增长返回栈；再次点当前 Tab 仍回记录根并滚到顶部 |
| “看这一天” | `NavigationStack` push | 系统返回按钮与边缘返回回到原尺度、原日期和原滚动位置 |
| 全部记录中的日期 | push 同一个日画布 | 返回上一级月份列表，不复制第二套日期页 |
| 日期编辑 | iPhone 系统 sheet；iPad form sheet | 取消 / 保存后回到日画布；有未保存内容时确认丢弃 |
| Plus 付费页 | 现有 feature gate | 关闭或购买后回到原日画布 / 原锁定位置；购买成功原地解锁 |
| iPad 与手机横屏 | 同一个 push，装在各自的自绘导航壳里 | 与竖屏一致；切到别的 Tab 会清空 `recordsPath`，日画布不跨 Tab 存活 |

日画布仍属于记录 Tab 的浏览层级，Tab Bar 保留。编辑是短任务，继续使用 sheet；日画布本身不是 sheet，也不做全屏 modal。

iPad 与手机横屏不是同一套导航 chrome：`TabletDesignView` 与 `PhoneLandscapeView` 各自把 `RecordsDesignView` 包进自己的 `NavigationStack`，标题由当前 Tab 决定而不是由被 push 的页面决定。所以“导航标题是日期、副标题是来源”在这两个壳里不会自动出现，需要日画布自己声明标题，并在两处实机确认。两个壳在离开记录 Tab 时都会 `recordsPath.removeAll()`——这是既有行为，写在这里是为了不被后来的人当成 bug 修掉。

## 日画布

### 1. 页面结构

从上到下固定为：

1. 原生导航标题：本地化日期；副标题显示来源，如“你记录的”“按今天的排班推算”。
2. 24 小时时间带：可视化当天的正常工作、加班、班中休息、睡眠、自主时间与无法分类。
3. 单一主结论：“属于你的清醒时间”，显示时长与当天占比。
4. 解释脚注：“班中休息 + 其余自主时间”；不再把两者误写成同一个指标。
5. 时间段列表：按时间顺序列出开始时间、类别、时长和来源。
6. 观察与专注记录：沿用当前日期详情内容，降到时间段之后。
7. Plus 用户的“编辑这一天”；免费用户显示温和说明，不提供点了才失败的伪按钮。

### 2. 指标命名

现有模型中：

- `freeMs` = 扣除正常工作、加班、班中休息和睡眠后剩余的清醒时间，对外名称继续是“自主时间”。
- `wakingFreeMs` = `breakMs + freeMs`，新增专用名称“属于你的清醒时间”。

不得继续用同一个“自主时间”标签同时表示两个值。19 个 locale 都要新增或修正文案，并为翻译提供“包含班中休息”的说明。

### 3. 时间轴与今天线

- 画布表示记录时区中的 civil day：从当地当天 00:00 到次日 00:00；夏令时日按真实 23 / 25 小时绘制和计算。
- 标准刻度可显示 0、6、12、18、24；DST 缺失或重复小时不伪造固定 24 小时分母，VoiceOver 读真实当天总时长。
- 只有选中记录时区中的今天时显示“现在线”。现在线之后若有可靠排班投影，以斜纹和“之后按今天排班推算”标注。
- 历史未记录日不拿当前排班回填为事实；只有已经符合 010 投影契约的内存推演才能显示，且必须带来源。
- 未来计划显示为计划，不进入真实记录统计，不提供记录页编辑入口。
- 现在线按分钟边界推进，不按秒。计时页每秒重绘是它的职责，日画布是回顾页面，不做第二个秒级刷新面。
- 页面不可见时停止推进；重新可见时一次性对齐到当前时刻，不补播中间帧。
- 正在进行的班次只允许现在线和末端片段的长度变化，不得让已经画好的区间重排或改变顺序——用户正在读的数据不能在手底下移动。

### 4. 跨夜班与编辑身份

日画布按 civil day 阅读，记录与编辑仍按班次锚点身份保存，两者不能混成一个概念：

- 20:00–04:00 的班次在两个 civil day 画布各显示实际相交部分；工作日计数仍只算锚点日一次。
- 构造日画布时必须读取会与当天窗口相交的相邻班次，不只读取同名 `dayKey` 的单个 `DayResolution`。
- 每个工作 / 加班段携带其班次锚点 `dayKey`，供编辑入口定位原始记录。
- 当天只涉及一个可编辑班次时，“编辑这一天”直接打开现有编辑 sheet。
- 当天涉及两个可编辑班次时，先用系统 `confirmationDialog` 按本地化时间范围选择班次，再打开对应 sheet。
- 纯计划、纯推算和没有可编辑原始输入的时间段不伪造编辑入口；今天 / 未来的运营变更仍走计时与排班设置链路。

### 5. 渲染与辅助功能

- 时间带可以使用 SwiftUI `Canvas`，但业务聚合与命中模型必须先在纯模型层完成。
- Canvas 只负责绘制；使用 `accessibilityRepresentation` 暴露按时间排序的类别区间，不暴露每个像素或每个采样桶。
- 每个可读区间的 VoiceOver 值包含：开始、结束、类别、时长、来源。
- 颜色不是唯一通道：推算使用斜纹，用户修正使用明确标记，选中使用描边，无法分类使用中性色与文字。
- 时间段列表是图表的完整无障碍替代表达，也是视觉用户查看精确时间的入口。

## 周 / 月选中日期摘要

当前五项指标卡改为紧凑摘要，避免月历之后立即出现第二张高密度图表：

- 日期与来源。
- 正常工作、加班两个最短摘要；无值时诚实显示未记录 / 休息 / 计划。
- 一行“属于你的清醒时间”。
- “看这一天”作为明确的层级入口。
- 冲突、睡眠来源和观察数量保留克制标记，详细内容进入日画布。

免费窗口外只显示专用锁定摘要，不构造上述真实值。购买完成后关闭付费页，原地恢复相同日期并显示真实摘要。

## 月格视觉语法

### 1. 一个日格的固定层级

每个约 48pt 月格按同一结构绘制：

1. 日期数字。
2. 底部迷你工时柱：柱高表示当天有效工时，正常工作为 `recordsWork`，加班作为柱尾分段使用 `recordsOvertime`。
3. 右上状态位：用户修正使用小点或铅笔；冲突继续使用警示符号；锁定使用锁。
4. 推算层：135° 斜纹；不得只靠降低透明度。
5. 选择：2pt DoneAt 橙描边或反相填充；今天使用同一交互色但不同结构，不能与选择完全相同。

月格现在被 `.dynamicTypeSize(...DynamicTypeSize.xxxLarge)` 封顶，48pt 里同时放日期数字、迷你柱和状态位，在大字号下必然打架。降级顺序固定为：先把迷你柱压到 2pt 底线，再让右上状态位退出绘制、只保留在 VoiceOver 值里；日期数字任何时候都不缩到不可读，也不允许月历失去日历语义。

### 2. 颜色边界

- `OWCDesign.accent` / `orangeDeep`：选择、今天、按钮、链接、交互反馈。
- `recordsWork`：正常工作。
- `recordsOvertime`：加班，只在数据图表内使用；始终有位置 / 纹理 / 标签第二通道。
- `recordsBreak`、`recordsSleep`、`recordsFree`、`recordsUnclassified`：继续在日时间带和占比图中复用。
- 人生阶段色只用于人生图，不进入记录状态、导航或 CTA。
- 红色只表示错误和破坏性操作，不表示“工作太多”。

### 3. 图例

月历下提供一行可折行的状态说明，至少覆盖：

- 实心 = 已记录。
- 斜纹 = 推算 / 计划，并按当前页面的具体来源写全。
- 修正标记 = 你改过。
- 锁 = 需要 Plus。

图例不能只出现一次后永久消失；在辅助功能字号和德语等长文案下允许改为信息按钮 / popover，但 VoiceOver 必须可达。

## 周视图

周视图不重做结构，但必须并入同一套语法。`RecordsWeekStrips` 现在按 `cell.overtimeMs > 0 ? recordsOvertime : recordsWork` 给整条日列上色——分类 token 是对的，语法是错的：有加班的一天会整条变成橙色，而不是拆成“正常工作 + 加班”两段。这正是原则 3 要消灭的“同一个事实两种说法”。

- 日列改为与月格迷你柱、年展开条相同的分段：正常工作在前，加班作为尾段。
- 推算、修正、锁定沿用月格的纹理与标记，不另立一套。
- 选中日列继续使用 DoneAt 橙描边；橙色不再承担“这天有加班”的含义。

## 年视图

年视图不重做。保留 011 已实现的双形态：

- 收起：密度 / 节奏画布，回答“什么时候更重”。
- 展开：12 条共享刻度的月度条，正常工作与加班分段，回答“月份之间差多少”。

本轮只对齐视觉语法：品牌橙不再同时表示工时与选择，推算纹理、用户修正和月份选择与月格使用同一含义。VoiceOver 仍只暴露 12 个月，不暴露数百个桶。

## 人生尺度的单一结论

人生点阵和阶段选择保留；在非沉浸状态下增加“一生的时间去了哪里”：

- 标题：“一生的时间去了哪里”。
- 来源：“按当前设置推算”。
- 主句使用中性描述，例如“按当前设置，到退休前约有 X 小时用于工作”。不得使用评判、劝诫或宿命化文案。
- 分配条固定使用正常工作、加班、班中休息、睡眠、自主时间和无法分类六类。
- 只有档案与排班输入足够形成可靠投影时显示数值；缺退休边界、工作阶段、平均睡眠或规则展开失败时，显示具体下一步，不硬凑百分比。
- 真实记录只覆盖 `recordsStartedOn` 之后的事实；更早人生与未来都按当前设置推演，并在详情中说明。不得把推演写入 Records、JSON 或 CloudKit。
- 沉浸展开继续只保留人生画布与收起按钮，不把总结塞进全屏画布。

## Plus 锁定体验与文案

锁定能力与 006 / 010 不变，只调整表达顺序：

1. 标题说明能力，例如“查看完整记录需要 Plus”。
2. 安心说明：“DoneAt 会继续保存在本机。解锁后即可查看完整记录。”
3. CTA：“查看方案”。

要求：

- 文案不得暗示数据会上云；用户未开启 iCloud 时只在本机。
- 免费用户今天及之前 6 天继续可看真实记录；窗口外、年、人生和汇总仍使用无真实值占位。
- 记录损坏、保存失败、导入失败和同步冲突不能被 Plus 文案覆盖；错误先解释数据状态，再提供可操作下一步。
- 19 个 locale 一次完成，不能把中文或英文直译复制到其它语言。

## 动效与触感

### 频率与目的

| 动作 | 目的 | 视觉 | 触感 |
| --- | --- | --- | --- |
| 点选月格 / 周列 | 状态指示 | 100–150ms 背景 / 描边变化；列表类单元不缩放 | 一次 selection |
| 进入日画布 | 空间一致性 | 系统原生 push，不自制转场 | 无额外触感 |
| 日画布数值更新 | 防止跳变 | 仅数字 `numericText` 或短交叉淡化；数据不滚动表演 | 无 |
| 打开编辑 | 系统任务呈现 | 系统 sheet | 不叠加额外触感 |
| 保存编辑 | 反馈 | 原地刷新时间带与摘要 | 一次 success |
| 切换记录尺度 | 状态指示 | 沿用现有约 200ms 交叉淡化 | 一次 selection |
| 双指分档缩放 | 状态指示 | 沿用现有阈值与轻微反馈；不做连续形变 | 跨档时一次 selection |

- Reduce Motion 下自定义空间动效改为交叉淡化；原生 push、Tab、sheet 保持系统行为。
- 日时间带不为每个区间播放入场动画，不让用户正在读取的数据移动。
- 一次操作最多一次主要触感；滚动、现在线刷新和自动加载不触发触感。
- 完整流程必须录屏，以正常速度和逐帧各看一次；截图不能替代动效验收。

## 数据与实现边界

### 新增纯展示模型

建议新增纯模型 `RecordsDayCanvasModel`，至少包含：

- civil day 的绝对开始 / 结束。
- 分类后的绝对时间段及来源。
- `TimeAllocationShare` 与“属于你的清醒时间”。
- 是否今天、现在线、投影起点与数据完整性。
- 与当天相交的可编辑班次锚点。
- 锁定状态；锁定实例不得携带真实时间段或聚合值。

模型构造放在 `Native/Models`，SwiftUI View 不做跨夜求交、加班裁剪、gap 推导或来源裁决。

**日画布是既有页面的升级，不是新增的第三套日期详情。** `RecordsRoute.day` 已经有目的地：`RecordDayDetailHost` → `RecordResolvedDayView`（均在 `RecordDayEditView.swift`），“全部记录 → 日期”现在就走它，里面已经有时间范围、来源标签、总时长和观察记录。日画布取代的是 `RecordResolvedDayView` 的正文；`RecordDayDetailHost` 的权限分支与 `RecordsLockedHistoryPlaceholder` 原样保留。如果不写这一条，Phase 3 的“移除第二套重复日期详情”会漏掉它自己刚制造的那一套。

### 共享规则边界

- `lib/countdown.ts` 继续是排班与有效 `segments` 的唯一来源。
- `lib/reminders.ts` 不因记录视觉变化而修改。
- 如果 `CountdownRules.js` 当前桥接结果不足以提供日画布需要的绝对片段或来源字段，扩展 TypeScript 生成入口并重建 bundle；不得把规则复制到 Swift。
- 生成的 `CountdownRules.js` 不手改、不提交。
- 日画布的 civil-day 求交、睡眠并集与显示聚合继续复用 / 扩展现有纯 Swift 模型；不得在多个 View 中各写一份。

### 持久化与隐私

- 不新增 Records schema、JSON schema、CloudKit record type 或 App Group 字段。
- 不记录用户浏览了哪一天、选了哪个尺度或看了多久。
- 不把原始记录、人生档案、薪资、睡眠或日画布截图发送到外部服务。
- Share URL 与现有分析事件不增加薪资或记录内容。

## 0. 核心判断：先重构班次模型，否则四个功能各修各的

现在 `CountdownState` 是「一对时间戳 + running」。3.1 要做的四件事全都打破它：

| 功能 | 打破了什么 |
| --- | --- |
| 隔日自动重启 | 一对时间戳只描述**当前**这一班，不知道下一班什么时候开始 |
| 午休暂停 | 班次中间要挖掉一段，剩余时间不再等于 `end - now` |
| 加班 | 结束时间可变，且要区分「原定」与「延后」 |
| 里程碑推送 | 进度必须按**有效工作时长**算，否则午休期间百分比照涨 |

如果各做各的，会得到四套互相打架的时间计算。所以第一步是把状态换成**分段模型**：

```
shift := { segments: [{start, end}, ...], plannedEnd, overtimeEnd? }
```

- 正常班次：一个 segment
- 开了午休：两个 segment，中间是午休区间
- 加班：追加/延长最后一个 segment
- 进度 = 已过去的 segment 内时长 ÷ segments 总时长
- 剩余 = segments 总时长 − 已过去时长（午休期间不减少）

**必须守住的既有约定**（AGENTS.md 里写着，3.0 的关键设计）：跨夜、工作日这些
业务规则只能存在于 `lib/countdown.ts`，Rust 不得有第二套实现。所以隔日重启不能
让 Rust 去"算下一班是什么时候"，而是**前端把下一班的 segments 一并算好写进状态**，
Rust 只做时间戳比较，到点切换。这样 Rust 依旧只有"比大小"这一种逻辑。

> 已定：一次做到位，见 §7-D1。

## 1. 安装与系统级本地化

### 1.1 Windows 安装向导多语言

`bundle.windows` 现在是**完全空的** `{}`，所以 NSIS 只有英文、图标是默认的。

Tauri 自带的 NSIS 语言文件已经核实过（`tauri-bundler/.../nsis/languages/`），
把 19 个界面语言映射过去是这样：

| 覆盖到的（15） | 界面语言 → NSIS |
| --- | --- |
| en → English，zh-CN → SimpChinese，zh-TW / zh-HK → TradChinese，ja → Japanese，ko → Korean，fr → French，de → German，es → Spanish，it → Italian，pt → Portuguese，ru → Russian，tr → Turkish，ar → Arabic，vi → Vietnamese | |

**缺口（4）**：`hi-IN`、`mr-IN`、`th`、`id` —— Tauri 尚未提供这四种 NSIS 语言，
安装器会回落到英文。**已定不补**（§7-D6）。zh-HK 也没有独立文件，与 zh-TW 共用
TradChinese。

配置形态：

```jsonc
"windows": {
  "nsis": {
    "languages": ["SimpChinese", "TradChinese", "English", "Japanese", "Korean", "German", ...],
    "installerIcon": "icons/icon.ico",
    "uninstallerIcon": "icons/icon.ico",
    "displayLanguageSelector": false
  }
}
```

- **不开语言选择器**：NSIS 默认按系统语言自动选，多一个弹窗只会拖慢安装。留作回退手段。
- **已知上游 bug**：多语言 NSIS 安装器的部分复选框文案可能串语言
  （[tauri#13041](https://github.com/tauri-apps/tauri/issues/13041)）。验收时要专门看这块，
  真踩到就减少同时启用的语言数。

### 1.2 安装包 / 卸载器图标

`src-tauri/icons/icon.ico` 已经存在，只是没被 NSIS 引用。配上即可，零成本。
`headerImage` / `sidebarImage` 需要额外做 BMP 素材，列为可选。

### 1.3 Windows 安装后的软件名多语言

**不做。** Windows 的开始菜单项、控制面板卸载列表、快捷方式名都来自单一的
`productName`。要按语言变名字，得往 exe 里塞 Win32 多语言资源表，Tauri 没有暴露这个
能力，得改 NSIS 模板 + 自定义构建步骤，而且每次 Tauri 升级都可能要跟着调模板。

大多数国际软件（VS Code、Chrome、Slack）在 Windows 上也都只有一个英文产品名。
保持 `Off Work Countdown`，本地化预算花在安装向导和应用内。

> 见 §7-D2。

### 1.4 托盘右键菜单多语言 —— 待复现的 bug

已排除的原因：`trayShowApp` / `trayMiniTimer` / `trayQuit` 三个键**19 个语言全都有**，
值也正常（中文是「显示应用 / 迷你计时器 / 退出」）。所以不是缺翻译。

链路是：Rust 用英文建菜单 → 前端在语言变化时调 `update_tray_menu` → Rust `set_text`。
可疑点按可能性排序：

1. **前端把错误吞了**。`updateDesktopTrayMenu(...).catch(() => {})` 什么都不做，
   命令失败与成功外观完全一致。这和本次修掉的 `show_main_window` 是同一类问题。
2. muda 在 Windows 上 `set_text` 未刷新已挂载的托盘 HMENU。
3. 首次触发时 i18n 资源未就绪，`t()` 返回 key 本身，之后不再重发。

**第一步不是猜，是让它出声**：去掉静默 catch，失败时写日志并在设置页暴露。
拿到 Windows 上的真实报错再定方案。

### 1.5 macOS 系统级本地化

应用内 UI 已经是 19 语言了，缺的是**系统那一层**：

- **菜单栏**：截图里始终是 `File / Edit / View / Window / Help`，Tauri 默认菜单是
  硬编码英文。要改得自己构建菜单并在语言切换时重建（和托盘同一套思路）。**建议做**，
  这是 macOS 上最显眼的一处英文。
- **应用名与 Finder 显示名**：需要往 `Contents/Resources/<lang>.lproj/InfoPlist.strings`
  注入 `CFBundleDisplayName`。Tauri 没有原生支持，要加构建后处理步骤。**建议不做**，
  理由同 1.3——但成本比 Windows 低，如果坚持要，可行。
- **`CFBundleLocalizations`**：声明支持的语言后，用户能在「系统设置 → 语言与地区 →
  应用程序」里单独给本应用指定语言。我们自己已有语言选择器，价值有限，**可选**。

## 2. macOS 通知授权引导

现在首次触发通知时，系统权限弹窗会毫无预兆地冒出来，用户往往顺手点了「不允许」，
之后所有提醒静默失效——而且 macOS **不会再弹第二次**。

改成标准的预授权引导：

1. 用户首次开启任一通知类功能（下班提醒 / 午休 / 微休息）时，先弹应用内说明：
   讲清楚会推送什么、不会推送什么（**明确写出不含薪资**）
2. 用户点「好」→ 调 `requestPermission()` → 系统弹窗
3. 授权成功后**立刻发一条测试通知**，让用户确认自己真的能收到
4. 若返回 `denied`（含之前拒绝过的情况）→ 显示引导文案 + 一键打开
   「系统设置 → 通知」，而不是反复请求

`isPermissionGranted()` / `requestPermission()` 由 `@tauri-apps/plugin-notification`
提供，已在依赖里。

## 3. 功能

### 3.1 倒计时结束后自动进入下一班

**现状**：到点后永远停在「倒计时已完成」，第二天上班还是那个画面。

**做法**：前端在写状态时，除了当前班次，一并算好**下一个工作日的班次时间戳**
（工作日、跨夜规则都在 `lib/countdown.ts`，不下沉到 Rust）。Rust 的托盘节拍器发现
`now > 当前班次结束` 且 `now >= 下一班开始` 时，直接切换到下一班并重置通知标记。

边界情况要处理：
- 今天是休息日 → 下一班可能是几天后
- 结束到下一班开始之间的空窗期 → 显示「今日已下班，下次上班还有 X」而不是空白
- 机器休眠跨越了整个下一班 → 不能补发一堆过期通知（现有 `NotificationMarker`
  已有类似防护，要一并覆盖）

### 3.2 午休（默认关闭，客户端独占）

设置：开始时间 + 时长（如 12:00 / 60 分钟）。

- 进入午休：推送友好提示，倒计时**暂停**（剩余时间不减少，进度条不动）
- 结束午休：可选推送「午休结束」
- 落到分段模型上就是把 `[12:00, 13:00)` 从 segments 里挖掉

**已定**：午休期间「今日已赚」停止累加（§7-D3）。午休区间不进 segments，
所以计时和计薪天然同口径，无需额外分支。

### 3.3 微休息提醒：喝水 / 起身（默认关闭，客户端独占）

设置：间隔（默认 60 分钟，可选 30/45/60/90）+ 提醒类型开关。

比"每小时固定弹"更好的两个改进：
- **按有效工作时长计时**，不是墙上时钟。午休和下班后不打扰。
- **文案带上下文**：「你已经连续工作 1 小时 30 分了」比「该喝水了」更有说服力。

文案库轮换，避免第三天就腻。

### 3.4 加班（客户端独占）

倒计时结束（或进行中）时提供「加班」入口，重新设定下班时间；进度与剩余时间按新
终点重算。加班时段在 UI 上要与正常工时**视觉区分**（比如进度条换色），
并计入当日/本周/本年累计。

**已定**：不支持倍率（§7-D4），按原时薪线性外推，只做视觉区分。

### 3.5 重构下班通知（客户端独占）

三档，替换现在生硬的「提前 15 分钟」：

| 档位 | 行为 |
| --- | --- |
| 关闭 | 完全不推送 |
| 简约 | 只在下班时推一条 |
| 里程碑 | 50% / 75% / 90% / 95% / 100% 各推一条 |

**文案原则**（每档准备 5–8 条轮换，19 语言）：
- 50%：过半，轻松基调
- 75%：「今天最难熬的部分已经过去了」
- 90% / 95%：临近，短促有力
- 100%：下班文案带上**累计数据**——「今天 8 小时 12 分，今年累计 1,204 小时」

**硬性约束：通知里绝不出现薪资数字。** 通知会出现在锁屏和通知中心，旁人可见；
这与 3.0 就定下的「金额可一键打码」是同一条底线。累计**时长**可以，金额不行。
这一条要写进 AGENTS.md 并加测试守住。

去重机制扩展现有 `NotificationMarker`：记录本班次已发的里程碑集合，避免重复发、
避免关掉再打开补发一串、避免跨天残留。

### 3.6 木鱼皮肤悬浮窗（客户端独占）

这是最有差异化的一条。竞品要么是纯番茄钟（专注清单、Focus To-Do），要么是浏览器
插件式的摸鱼倒计时，**没有把"下班倒计时 + 累计工时 + 解压交互"合在一起的**。

交互：
- 悬浮窗可切皮肤，木鱼皮肤下点击 = 敲一下，出音效 + 一次性显示当前下班百分比
- **首次敲击必须静音**，只提示「可在设置中开启音效」——办公室里突然出声是灾难
- 可选：累计敲击数（纯本地，不上报）

**架构上有个现成的便宜**：木鱼皮肤适合用 HTML/CSS/音频实现，也就是现在的
WebView 迷你窗（`/[lang]/mini`）。而这次为验收 Windows 迷你窗加的
`OWC_FORCE_WINDOWS_MINI` 开关**已经证明这个窗口能在 macOS 上正常跑起来**。
把它从 debug-only 提升为正式能力即可，macOS 于是同时拥有：

- 菜单栏原生面板（轻量常驻，保持现状）
- WebView 悬浮窗（带皮肤和音效，可选开启）

这正好对应你说的"macOS 可能需要同时保留两种计时器"，而且几乎不用新写窗口管理代码。

**音效已定用 Web Audio 实时合成**（§7-D7），不引入音频文件。首次敲击静音这条要求，
恰好和「AudioContext 必须由用户手势解锁」的浏览器限制吻合：第一次敲击用于解锁并弹出
「可在设置中开启音效」的提示，从第二次起才可能出声。

## 4. Web 端如何表现客户端独占功能

3.1 有五个功能标了「客户端独占」。Web 端有三种处理方式：

1. 完全不显示 —— Web 用户不知道有这些
2. 显示但禁用 + 引导下载客户端 —— 转化入口，但设置页会被撑长
3. 只在下载页列出对比 —— 现有 `download` 页已有对比表，扩展它

**已定**：只做 3（§7-D5）——扩展 `download` 页对比表，Web 设置页不放灰掉的开关。

## 7. 已定决策

七项均已确认，下文即实施口径，不再复议。

**D1 — 分段班次模型一次做到位。** M1 先重构成 `segments + plannedEnd + overtimeEnd`，
午休、加班、隔日重启、里程碑推送全部建在它上面。M1 没有用户可见收益，但避免了后面
四次返工。**M1 合并前不开任何功能分支。**

**D2 — Windows 安装后的软件名保持单一英文 `Off Work Countdown`。** 不改 NSIS 模板、
不往 exe 塞 Win32 资源表。本地化预算花在安装向导和应用内。

**D3 — 午休期间「今日已赚」停止累加。** 午休区间不进 segments，因此既不计时也不计薪，
两个口径天然一致。设置页的午休开关下方需要一句说明，讲清楚金额不再等于
「班次总时长 × 时薪」。

**D4 — 加班不支持时薪倍率。** 按原时薪线性外推，只在进度条和汇总里把加班时段
视觉区分出来。理由：各地加班规则差异极大，支持倍率会让这个估算工具被当成工资计算器，
承担它不该承担的准确性预期。

**D5 — 客户端独占功能只在下载页对比表露出。** 扩展现有 `download` 页的对比表，
不在 Web 的设置页放置灰掉的开关。

**D6 — 缺失的四种 NSIS 语言不补。** `hi-IN`、`mr-IN`、`th`、`id` 的用户会看到英文
安装向导，应用内仍是母语。安装向导只看一次，性价比不足以承担四份无法校对的翻译。

**D7 — 木鱼音效用 Web Audio 实时合成，不引入音频文件。** 体积为零、无授权问题，
并且音高与衰减可调——连击时微调音高就能避免单调。需要处理的是浏览器自动播放策略：
首次敲击本来就要静音（见 §3.6），正好与「必须由用户手势解锁 AudioContext」这一限制
天然吻合。

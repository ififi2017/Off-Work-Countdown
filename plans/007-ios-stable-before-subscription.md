## 已定口径（面试锁死，细节以 surfaces 文档为准）

计时 Tab 有排班时只在：**上班倒计时 → 下班倒计时（午休 / 加班穿插）→ 结算 → 按结束日次日零点切休息或上班倒计时**。休息日：弱倒数（与上班倒计时同一进度口径）+ 本周 / 本年结算 + 「手动计时」。未排班：每天「手动计时」决定今天有没有班。

- 欢迎页最后一页才是班次表单（时刻 + 固定星期 / 单双休 / 轮班，或先不排班）。老用户不重跑欢迎页。
- 上下班时刻只在排班设置页改。编辑留在草稿，点保存后仅在改动仍会影响今天时询问三项；「今天也改」清掉提前上班、提前下班和加班，不清手动计时。
- 提前上班只在上班倒计时：开始=现在，下班时刻不变。不做迟到。
- 提前下班只在下班倒计时；与计划结束都是下班，用户优先。结算没有「返回」。
- 加班可在计划结束前登记；结算再加 = 「其实还没走」。
- 「接下来」只在上班 / 下班倒计时。分享只在上班 / 下班倒计时和结算，文案跟屏幕上的钟；链接只带排班时刻。
- 有排班没有停止倒计时。规则错误用横幅，不停表。
- 不说「强制计时」「武装」。休息日与未排班的主按钮都叫「手动计时」；有排班的休息日进班后用横幅取消，不留「上过班」。

完整形态、壳层、日历缝、分享表见 [docs/IOS-TIMER-SURFACES.md](../docs/IOS-TIMER-SURFACES.md)。

## 实现时的判断

落地时未再问你、按我认为的最优解做了的取舍。审查时可对照其他选项。

1. **今日覆盖怎么存**
   选：覆盖层仍绑在「当前班次结束落在的日历日次日零点」，只用来算**这一班**的时刻。`nextShift*`、提醒的 `next:`、小组件 `widgetShifts` 走底图，所以「只从下一班起」改的是下一班，不是把旧 17:00 画进未来一年。
   未选：整份 `rulesInput` 都用覆盖层（小组件关掉 App 后会沿用旧时刻直到再打开）；或 `pendingSchedule` 到下一班才写底图。

2. **休息日 / 上班倒计时进度方向与分母**
   选：两段都按「已过去」从 0 增到 100。休息态从上一次结算日次日 0 点走到目标工作日 0 点；目标工作日切上班倒计时后，从 0 点走到上班点。大数字始终连续倒数到上班点，条只在明确的态切换处重置。
   未选：继续画剩余比例（00:08 距 09:00 还有近 9 小时却显示 98.6%）；或让跨周末的大分母带进周一早晨（仍会在剩整夜时接近满格）。

3. **提前上班取整**
   选：秒归零到当前分钟，避免每秒改开始点导致快照抖动。
   未选：精确到秒（更「现在」，但规则桥每秒都换 startTime）。

4. **欢迎页不问「今天也改」**
   选：直接写入底图。还没有在跑的班。
   未选：欢迎页也弹三项（新用户第一次就要理解覆盖层）。

5. **有排班时 `stopCountdown` 对用户是空操作**
   选：UI 不再调用；内部对已排班用户也不清 `countdownStarted`。未排班次日零点仍停会话。
   未选：保留隐藏的停止开关给调试。

6. **轮班天数 / 大小周当前周类型**
   选：仍直接写底图，不弹「今天也改」。问的是会立刻改今天这一班长什么样的：时刻、午休、工作日、排班模式、先不排班。
   未选：每次点 stepper 都弹（很吵）。

7. **连续两次「只从下一班」**
   选：覆盖层被换成「上一次已提交的底图」。今天看到的是中间那一版，不是最初那一版。
   未选：覆盖层只在第一次写入、之后只改底图（今天一直钉死第一次的旧值，更难解释）。

8. **分享链接的时刻**
   选：底图 `startMinutes`/`endMinutes`，不含今日覆盖和提前上。让别人套用一班。
   未选：有效窗口（别人会套到你今天提前上的 8:00）。

9. **英文主按钮**
   选：`Time today`，中文「手动计时」。
   未选：`Manual timing`（更直译，不像按钮）。

10. **升级时空的固定星期集合**
    选：填回周一到周五。
    未选：自动切先不排班（会改变老用户的周末含义）。

11. **iPad 沉浸式**
    选：底栏主动作始终在，不再藏进侧边栏。列顶对齐以免按钮被滚走。
    未选：只在侧边栏里放按钮（违反口径）。

12. **未排班提前下班**
    选：与有排班一样进结算，次日零点再问。不再把提前下班当成「返回」。
    未选：一按就停会话回询问页。

13. **`dismissedCompleted`**
    选：不再写入，方法留成空操作以免旧调用崩。升级后的结算不可再回到配置页。
    未选：迁移时清掉所有旧 dismiss 标记（多一次 UserDefaults 扫）。

14. **提前下班不清会话边界**
    选：`clockOffEarly` 保留 `activeCountdownEndAtMs`。未排班结算仍是「这一次」，次日零点才停会话。若清掉，次日早上规则会生成新班，nil 边界的迁移路径会把它当成还在跑。
    未选：提前下班立即停未排班会话（用户看不到当天结算）。

15. **小组件是否走底图 `scheduleMode`**
    选：走 `followsSchedule`（含今日覆盖）。「只从下一班起」改成先不排班时，今天的小组件仍按今天的班走。
    未选：继续看底图 `scheduleMode`（今天会提前变成空闲）。

16. **计时首页配置源文件**
    选：主路径不再引用；`ShiftSetupView.swift` / `ShiftHeroCard.swift` / `ShiftSetupTimelineView.swift` 仍留在工程里，避免为删文件改 `pbxproj`。横屏 / iPad 里已删掉未引用的私有配置视图。
    未选：连同 pbxproj 一起删掉这三个文件（下次专门清理工程文件时再做）。

17. **设置那问用 Alert**
    选：`.alert` 三个按钮都画得出来。
    未选：`confirmationDialog`（iOS 26 把它收成锚定菜单，取消项不画，点外面才回滚）。

18. **午休 / 加班不换屏身份**
    选：`running` / `lunch` / `overtime` 共用 `surfaceIdentity`，整屏不 cross-fade。
    未选：`.id(phase)`（穿插在视觉上像换了页）。

19. **夜班结算缝写在规则束里**
    选：`findEndedShiftOnEndCalendarDay` 进 `snapshot()`，Swift 继续只渲染。周六 06:30 仍是周五那班 `remainingMs = 0`，撤销窗口也能再匹配上。
    未选：在 Swift 里按结束日历日重写一班（两套答案）。

20. **休息日通知**
    选：`shiftReminders` 在休息日和结算丢掉 `current:`，Live Activity 那道门之外通知也走同一条。
    未选：只靠 `publishesLiveSurfaces`（周六仍会预约 09:00–17:00 的幻影班）。

21. **午休开关**
    选：整行 Button，Toggle 只展示、不接 Binding。
    未选：自定义 Binding 里 `showChangePrompt = true`（SwiftUI 发现值没变，那问不会出来）。

22. **提前上班的下一班**
    选：和覆盖层一样，`nextShift*` / `next:` 走底图。
    未选：只在 `todayOverride != nil` 时叠加（08:00 提前上班会把明天也改成 08:00）。

23. **强制夜班结算缝**
    选：规则输入多带 `forcedWorkdayStartMs`，`findEndedShiftOnEndCalendarDay` 把那一天当工作日。
    未选：把那天塞进 `workdays`（会让周六晚上变成排班班次）。

24. **排班 / 午休页何时提交**
    选：页面持有可跨旋转的草稿；点右上角保存才提交并判断今天是否受影响。带草稿返回时，原生 `confirmationDialog` 只负责「继续编辑 / 放弃修改」，且挂在返回按钮上。
    未选：选择器合上立即询问；或页面退出后再弹是否保存。

25. **保存后是否还要问今天**
    选：规则桥比较当前 / 候选时间轴。已结束班次且候选仍结束、休息日纯时刻、原 / 新午休都已过去时，直接保存到后续班次；只有今天剩余表面会变化才给三项 Alert。
    未选：每次保存无条件追问，或在 Swift 里另写一套班次判断。

26. **休息日 / 未排班的「只从下一班起」**
    选：没有进行中的班时，覆盖层期限用今天次日零点。
    未选：没有班就不建覆盖层（休息日勾上今天会立刻变成上班）。

27. **「今天也改」与手动计时**
    选：清提前上/下和加班，不清 `forcedWorkdayDate`。今天已经变成正常工作日后才去掉多余的强制标记。
    未选：`clearTodayAdjustments()` 一律清手动计时。

28. **跨零点加班结算**
    选：`findEndedShiftOnEndCalendarDay` 用 effective end，并回看最多两天。
    未选：只按当天计划 `endTime` 判断（日班加班过零点会直接跳到下一班）。

29. **提前上班二次确认**
    选：与提前下班同一套两下确认；上班倒计时与下班倒计时用不同 `surfaceIdentity` 走现有态过渡。
    未选：一按即切、无动画。

30. **欢迎页排班**
    选：与其它欢迎页一样用 Spacer 垂直居中；模式行含固定星期 / 单双休 / 轮班 / 先不排班。
    未选：大小周和倒班只放设置（新用户在欢迎页选不了）。

31. **Live Activity 下班兜底通知**
    选：与 `shiftReminders` 同一道当前班门。
    未选：只看 `publishesLiveSurfaces`（周六会预约幻影 17:00）。

## 验收场景（产品，不是实现清单）

1. 新用户走完欢迎页，计时页已经在倒计时（或未排班询问），不必再「应用配置」。
2. 老用户打开即进对应态，不重看欢迎页；改时刻只能去设置。今天仍会受影响才询问覆盖；已结束班次或休息日纯时刻直接保存到后续班次。
3. 周一 08:00 是上班倒计时；提前上班后变成下班倒计时，开始为现在、17:00 不变。
4. 没有「其实这时才开始」；10:00 打开仍从排班开始点算，应用不说迟到。
5. 午休时屏幕和分享都数回来，不切独立午休职能页；App、Widget、Live Activity 的进度在午休空隙都暂停。
6. 15:00 提前下班进入结算；撤销仅当天有效；「返回」不存在；周六是休息不是庆祝周五。
7. 结算后再加班，提前下班记录消失，钟继续走。
8. 周六好好休息 + 弱倒数到周一上班；进度按已过休息时段增长，周一 0 点切当天上班前进度；手动计时可取消回休息；Widget 文案与进度一致。
9. 先不排班每天问；开始一次后次日零点再问。
10. 设置里把 17:00 改成 18:00：今天仍未结束则可取消 / 只从下一班 / 今天也改；今天已结束且 18:00 也已过则直接保存到下一班；若新结束点仍在未来则继续询问。午休同理只看原 / 新窗口是否还影响今天。
11. 勾不掉最后一个工作日；切先不排班仍要问今天。
12. 分享：上班前说距上班；链接仍是排班时刻；图和链接无薪资。
13. 规则包缺失时能看到错误，排班不会被停掉，周末 Widget 不会因此改成「好好休息」直到重新开始。

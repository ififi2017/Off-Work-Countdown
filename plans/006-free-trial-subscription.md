## 一句话

App Store 免费下载，欢迎页之后展示一次可跳过的付费页，提供 7 天试用，之后按月 / 年订阅，
或一次性买断终身（非消耗型商品，不是订阅）。**倒计时本体永久免费**，卖的是记录、人生视图
与专注。

## 必须先说清的一个事实：通用购买绑住了两端

这是本方案唯一的硬约束，先摆在最前面：

- iOS 与 Mac App Store 共用**同一个 App 记录**：bundle id
  `com.rainif.offworkcountdown.macappstore`，App Store id `6802803318`。
- Mac App Store 上架的是 `src-tauri` 打出来的包，iOS 上架的是 `src-mobile/ios` 的 SwiftUI 包。
  这是 [ADR-MOBILE-D0](../docs/ADR-MOBILE-D0.md) 已锁定的通用购买决策，`check:ios` 也在断言
  这个 bundle id。
- 通用购买 = 一个记录 = **一个价格**。**记录已改为免费下载**（2026-08-27 确认；原先 US$0.99 / ¥8 买断不再是当前标价）。Mac 历史上那 1 单买断仍按下文用兑换码处理，不为此写迁移。

因此 iOS 与 Mac App Store **已经同为免费下载**。006 要做的不是再改一次标价，而是在免费下载之上加试用、订阅和终身买断 IAP；倒计时本体保持免费。

**已定：接受这个连带后果，整个记录改为免费 + IAP。** 代价是放弃 Mac 端的买断收入——而 Mac 端
至今的销量是 1 单，买家是作者本人，所以实际损失为零。想在 Mac 上使用记录功能的人，走 iPad
版在 Apple Silicon Mac 上运行这条路径。

**没有历史买断迁移负担。** iOS 尚未上架，macOS 唯一一单是作者自己，所以本方案**不实现**
`AppTransaction.originalAppVersion` / cutoff 那一整套历史用户判定：它是一段不可回测、
sandbox 里还给不出可信值的复杂逻辑，为一个已知为空的用户群写它没有意义。真要照顾那一单，
发一个兑换码比写一套判定便宜得多。

## 免费与付费的边界

这张表是本文件与 [002](002-records-life-focus.md) 的接口，两边必须一致。

分三层。第一版把「免费」和「付费」直接对立，结果是同一个实体（当日覆盖）一边被写成永久
免费的临时调班、一边被写成付费的单日编辑。三层才说得清。

**一、免费运营数据——始终可创建、可编辑。** 这些是让倒计时正常工作的输入，不是历史资产：

| 能力 | 说明 |
| --- | --- |
| 下班倒计时、排班设置 | 应用的本体 |
| **今天及未来**的当日覆盖（临时调班、请假、补班） | 它服务的是「明天几点下班」，属于运营输入 |
| 日历例外（节假日 / 补班标记） | 同上 |
| 薪资推算与今日收入、生物识别门禁 | 现有能力，不回收 |
| 小组件、实时活动、通知与微休息提醒 | 现有能力，不回收 |
| 分享图、主题与语言 | 现有能力，不回收 |

**二、数据权利——始终可达，不需要付费也不需要试用。**

| 能力 | 说明 |
| --- | --- |
| 已有记录的只读查看，**全历史不限期** | 每日结论、来源、已有观察，一个朴素列表，能一直翻到头 |
| 完整导出（JSON） | 见 002 的导入导出契约 |
| 删除单条 / 全部 / iCloud 副本 | 见 002 的隐私承诺 |
| **已经开启的 iCloud 同步** | 开启需要付费能力，但开启后不回收——见下方 |

**三、付费能力——试用或订阅。**

| 能力 | 说明 |
| --- | --- |
| 周 / 月 / 年图表与**跨日聚合统计** | 分界线就在这里：免费能逐日看，付费才把它们加起来 |
| **过去日期**的当日覆盖编辑 | 修历史是回顾能力，不是运营需要 |
| 人生视图 | |
| 任务与专注（P2） | |
| **开启** iCloud 同步 | 入口可见，点击弹付费页；开启之后不回收 |
| 新观察日志的采集 | 见下方 |

### 到期之后到底发生什么

- 第一、二层照常，一点不减。
- 第三层停止，**但 iCloud 同步除外——它照常继续**。原因是技术性的、也是对用户更好的：
  SwiftData 的自动镜像没有暂停语义，库建成 `.private` 就一直在同步，「停止同步但不迁移」
  根本写不出来；而真去迁回本地，续订时就要合并「到期期间的本地修改」与「云上旧数据」，
  那是整个方案里最容易丢数据的一段代码。所以口径是：**开启同步要付费，保持同步是数据
  权利**。到期用户仍能进记录 Tab 看逐日列表，但同步这件事本身对他是无感的；而关掉它只会
  让某台设备静默变陈旧。
- **停止采集新的观察日志。** 初稿在这里写错了：当时的理由是「否则重新订阅时历史会留下
  补不回来的洞」，但 [002](002-records-life-focus.md) 明确写着观察不参与聚合、缺一段也不
  构成历史空洞。理由不成立，剩下的就只是「用户看不到任何收益，应用还在记录他的使用
  行为」——那不该做。已有的观察照常保留、可查看、可导出、可删除。
- **付费墙只加在 UI 层，永远不加在写入层。** 这条仍然成立，只是它管的是第一层：到期后用户
  改明天的班、标个补班，照样写得进去。

## 定价

| SKU | 国区 | 外区 | 说明 |
| --- | --- | --- | --- |
| 月 | ¥6 | $1.99 | 最低门槛，主要作用是让终身显得划算 |
| 年 | ¥28 | $9.99 | ≈ 4.2 个月，年比月省一半多 |
| 终身 | ¥58 | $24.99 | ≈ 2.3 年，第三年回本；国区用户偏好买断，这是主推 |

外区按当地购买力定价而不是汇率换算，这是 App Store 的普遍做法。

### 竞争力评估

**¥58 对现在的 App 贵，对 P1 之后的 App 不贵。** 国区单一用途工具的终身价大致落在
¥18–¥68 这个带上，¥58 属于中上但不离谱。真正的问题不是数字而是**卖的是什么**：今天这个
App 是「倒计时 + 薪资推算 + 小组件」，¥58 硬墙很难成立；等记录、人生视图与专注都在了，
同样的 ¥58 面对的是一个完整产品。

所以定价不变，**变的是开墙时机**——见下方发布顺序。

风险项，需要在上线后观察而不是现在拍板：

- 国区用户对小工具订阅的抵抗力强于欧美，月订阅的转化可能显著低于终身。如果终身占比
  超过八成，说明月/年订阅只是在给终身做锚，这不是坏事，但不要再为订阅追加功能。
- 这个 App 有很强的一次性传播流量（小红书一类）。「倒计时永久免费」正是为了不把这批
  流量在第 8 天全部关在门外。

## 试用：7 天

- 7 天正好覆盖一个完整工作周，价值已经展示完毕，决策不拖延；也让转化数据回来得更快。
- 试用是 App Store Connect 订阅组里的 **introductory offer**，不是代码里的逻辑。代码只负责
  读取当前 entitlement，不自己计时。
- **只给年订配置试用，这是商业选择而不是平台限制。** 组内每个订阅商品都可以各自配置
  introductory offer；受限的是**用户**——每位用户在一个订阅组里只能兑换一次。我们选择只给
  年订配，付费页的默认 CTA 也是年订：试用结束直接转 ¥25，客单价最高、churn 最低。月订与
  终身仍然可选，只是没有试用。
- **资格必须查询而不是假设。** 用 StoreKit 的资格结果决定要不要显示「7 天免费试用」字样——
  已经用过试用的用户看到的必须是直接的价格，否则是误导，也会被审核挑出来。
- **查到资格之前，按钮不能叫「开始免费试用」。** 商品加载是延迟发起的（见下方网络一节），
  所以静态那一屏的 CTA 只能是中性的「查看方案」，拿到资格后再变成「开始 7 天免费试用」或
  直接的价格。
- 终身买断是非消耗型商品，不参与试用。
- 必须用 StoreKit Configuration 文件在本地测通，并在真实 TestFlight 场景复验一遍。

## 付费页出现在哪里

1. **欢迎页之后展示一次，可跳过。** 介绍记录与人生视图，CTA 是中性的「查看方案」——在商品
   与资格加载回来之前，不能写「开始 7 天免费试用」，因为还不知道这个用户有没有资格。跳过后
   直接进入倒计时，不再自动弹出。这一步的作用是让每个新用户都知道你在卖什么，而不是拦住他。
2. **墙不在记录 Tab 门口，在它内部的付费能力上。** 这一条上一版写反了，会直接把已经定稿的
   数据权利锁在墙后：

   - **记录 Tab 本身永远可进**，全历史逐日只读列表永远可看，导出与删除永远可达；
   - 付费页出现在**具体的付费能力**上：周 / 月 / 年聚合图表、比例统计、人生视图、编辑过去
     的日期；
   - 任何一次弹出的付费页都必须有醒目的「继续只读查看」返回路径，**不能做成硬门**。

3. 设置页常驻一个入口，用于订阅、恢复购买与管理订阅。

## 技术选型：直接用 StoreKit 2，不接 RevenueCat

RevenueCat 的价值在跨平台（安卓 / Web 订阅）、定价 A/B、跨端账号打通与收据校验托管。这个
项目一个都用不上：只有 Apple 平台、只有 3 个 SKU、没有服务端。而它的成本是真实的：它是
第三方服务，会把用户标识与购买记录发到**自己的**服务器，因此隐私标签要新增第三方 SDK 的
数据收集申报、要补 SDK 隐私清单，也要改引导页文案。用 StoreKit 则只与 Apple 通信，不引入
第二个数据接收方。

以后真要卖安卓或做定价实验时再迁不晚——RevenueCat 支持接管已有的 StoreKit 购买。

### 但这不代表「完全不发网络请求」——旧承诺必须改

初稿把「不接 RevenueCat」写成了「所以能保住不发网络请求」，这是错的。`Product.products(for:)`
本身就是向 App Store 取商品与本地化价格。付费页确实会在欢迎页之后展示给每一个新用户，
但**只要商品加载是延迟发起的**（见下方第 2 点），跳过它的人就不会触发这次查询。真正不能
承诺的是「一个网络包都没有」——启动时的权益对账属于系统行为，Apple 没有承诺它绝不联网。

两件事要做：

1. **文案改成准确的**，全部 19 个 locale：

   > 倒计时和本地数据可离线使用。应用仅在加载购买信息、恢复购买，或你主动开启 iCloud
   > 同步时连接 Apple 服务；你的工作与薪资数据不会发送给开发者。

2. **把商品加载推迟到用户真的要看价格时。** 欢迎页之后那一屏先渲染静态介绍，CTA 是中性的
   「查看方案」；只有用户点它，才调 `Product.products(for:)` 并查询试用资格，拿到结果后
   才显示「开始 7 天免费试用」或直接的价格。

   验收条件要写成**我们能控制的行为**，不是「一个网络包都没有」：启动时的
   `Transaction.currentEntitlements` 属于系统行为，Apple 并未承诺它绝不联网，把它写成产品
   可控的验收项是自欺。准确的说法是——**跳过付费页时，不调用 `Product.products(for:)`、
   不查询试用资格、不创建 CloudKit 同步容器、不加载任何价格。**

实现边界：

- 使用 StoreKit 2 的 `Transaction.currentEntitlements` 与 `Product.SubscriptionInfo`；部署目标
  足够高，不需要兼容旧 API。
- **权益判定收敛在一个入口**，不在各个视图里散落 `isPro` 判断。这既是可读性，也让将来换实现
  只改一处。
- 状态必须区分「已验证为无权益」与「尚未验证 / 暂时失败」，不能把网络失败当成未订阅把用户
  锁在外面，也不能「第一次看到就永久缓存」把未验证当成已购买。
- 价格一律用 `displayPrice` 等 StoreKit 提供的本地化字符串，不在 19 个 locale 里硬编码货币。
- 付费页必备要素（Apple 3.1.2 审核会逐条看）：本地化价格、订阅周期、试用时长与**试用后的
  价格**、恢复购买按钮、服务条款与隐私政策链接、清晰的自动续费说明。缺一项就是被拒的
  理由，**不能「零 UI 发版」**。
### 权益状态机

「有没有订阅」不是一个布尔值。判定必须覆盖下面每一行，缺一行就是一类线上事故：

| 状态 | 是否授权 | 说明 |
| --- | --- | --- |
| `subscribed` | 是 | 正常订阅中（含试用期内） |
| `inGracePeriod` | **是** | Apple 正在重试扣款，此时切断是把用户当欠费处理 |
| `inBillingRetryPeriod`（无宽限期） | 否 | 已进入重试且没有宽限期，按未订阅处理 |
| `expired` | 否 | 正常到期 |
| `revoked` | 否 | 退款或家庭共享被撤销 |
| 交易带 `revocationDate` | 否 | 退款，无论商品类型；终身也会被撤销 |
| 终身（非消耗型，未撤销） | **是，且永久** | 不参与续期状态判定 |
| 购买待批准（Ask to Buy / pending） | 否，但**不是错误** | 显示「等待批准」，不要弹失败也不要当未订阅劝购 |
| 尚未验证 / 网络失败 | 有截止日期的有条件沿用 | 见下方，不是无限期 |

**「退款」和「试用期内关掉自动续费」不是同一件事**，不能用一套分支处理：前者是撤销
（`revocationDate`，权益立刻消失），后者只是不再续期（当前周期内仍然 `subscribed`，权益
保留到周期末）。Apple 把续期状态与撤销日期分成两套 API，实现上也必须分开读。

### 离线时的授权必须有截止日期

初稿写的「网络失败沿用上次已验证结果」如果落成缓存一个 `isPro = true`，月订用户只要
离线跨过到期日就能永久保留权益。正确的写法：

- **缓存的是经过验证的交易和已验证的订阅状态（renewal info），不是布尔值。** 只缓存交易
  不够——截止日期在哪，取决于当前处于哪个状态。
- **每个状态有各自的截止值**：

  | 状态 | 离线授权到 |
  | --- | --- |
  | `subscribed` | 交易的 `expirationDate` |
  | `inGracePeriod` | renewal info 的 **`gracePeriodExpirationDate`** |
  | 终身且未撤销 | 无截止日期 |

  宽限期这一行是关键：进入宽限期时，正常订阅期**已经过去了**，`expirationDate` 早就是过去
  时间。拿它当上界会把宽限期用户当场切断——而那正是 Apple 要求继续提供完整服务的一段。
  这两个日期必须分开读、分开缓存。

- **截止值一律来自 Apple 的签名内容，本地绝不自行延长。**

**`currentEntitlements` 拿不到宽限期需要的东西**，这一点上一版写错了。它产出的是
`Transaction`——宽限期中的交易确实在里面，但返回值**不会告诉你它处于哪个状态**，也不带
`gracePeriodExpirationDate`。状态与已签名的 renewal info 来自 `Product.SubscriptionInfo.Status`。
所以两个来源都要读：

| 时机 | 读什么 |
| --- | --- |
| 启动对账 | `Transaction.currentEntitlements` 拿有效交易，**再**读取并验证订阅的 `Status` / renewal info |
| 运行期间 | `Transaction.updates`（新交易、退款）**加上** `Product.SubscriptionInfo.Status.updates`（状态变化） |

第二行的后半句不是冗余：**扣款失败进入宽限期时，可能根本没有一笔成功的新交易**，只有订阅
状态变了。只挂 `Transaction.updates` 会完全错过它，刚修好的宽限期截止值也就永远读不到。

另外两条实现要求：

- **三个入口各管一段，都不能缺**（见上表）：`currentEntitlements` 对账、`Transaction.updates`
  接交易变化、`Status.updates` 接状态变化。应用没运行时发生的变化，下次启动由
  `currentEntitlements` 加 `Status` 一起对出来。监听器在启动时就挂上，收到已验证交易后必须
  `finish()`，否则会被反复投递。
- **验证失败的交易一律不授权**，不要「先放行再补验」。

### 终身与订阅可能同时存在

终身是非消耗型商品，订阅会一直续期到用户自己去取消——**买终身不会自动取消已有订阅**。
初稿写的「买过终身就永远不再展示任何订阅入口」会把用户的管理入口一起藏掉，结果是他继续
被扣款却找不到地方停。正确做法：

- 已有活跃订阅的用户点终身时，**购买前**明确提示：这不会自动取消你现在的订阅，买完请去
  「管理订阅」关闭它。

## 验收场景

1. 全新安装：欢迎页 → 付费页 → 跳过 → 倒计时完全可用，无任何功能受限提示。
2. 开始 7 天试用：聚合图表与人生视图立刻可用，设置页显示试用剩余天数与到期日。
3. 试用到期未续：**记录 Tab 仍可进、逐日列表仍可看**，只有聚合图表与人生视图弹付费页；
   倒计时、排班、薪资、小组件照常；导出与删除入口仍可达。
4. 订阅中途取消但周期未结束：权益保留到周期末，不提前收回。
5. 已有活跃订阅时购买终身：购买前收到提示，购买后管理订阅入口仍在，直到旧订阅自然结束。
6. 扣款失败进入宽限期：权益不中断；宽限期结束仍未成功才收回。
7. 退款 / 家庭共享撤销：权益立即收回，且与「取消自动续期」走不同分支。
8. Ask to Buy 待批准：显示等待状态，不弹购买失败，也不继续劝购。
9. 已用过试用的用户打开付费页：不显示「7 天免费」，直接显示价格。
10. 应用运行时发生续期或退款：`Transaction.updates` 收到后权益随之更新。
11. 应用**未运行**时订阅过期或被退款：下次启动由 `currentEntitlements` 加订阅 `Status` 一起
    对账出正确状态。
12. 扣款失败进入宽限期且**没有新交易产生**：`Status.updates` 收到状态变化，权益不中断。
13. 换设备后恢复购买：不重新付费即可恢复权益。
14. 无网络启动：不把网络失败当成未订阅，已验证过的权益在**其状态对应的截止值**之前仍然生效。
15. 月订用户离线跨过到期日：权益到期即失效，不因为一直联不上网而永久保留。
16. 跳过付费页的用户首次启动全程：不调用 `Product.products(for:)`、不查资格、不建 CloudKit
    容器、不加载价格。
17. 宽限期用户离线：授权持续到 `gracePeriodExpirationDate`，不在 `expirationDate` 就被切断。
18. Sandbox / TestFlight：试用、续订加速周期、退款各跑一遍，不用 sandbox 的版本号做任何判定。
19. 订阅到期：停止采集新观察；**iCloud 同步照常继续**；排班与未来临时调班照常可编辑；
    **全历史只读列表仍可一直翻到头**，导出与删除入口仍可达；本地数据一条不少。
20. Mac App Store 版：免费下载，无 IAP 入口，无任何指向 iOS 订阅的死链。

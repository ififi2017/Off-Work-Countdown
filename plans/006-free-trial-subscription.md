# 006 — 从买断到「免费下载 + 试用 + 订阅」

- **Status**: DRAFT
- **Reviewed against**: 6576842
- **Severity**: HIGH
- **Category**: 商业模式 / StoreKit / App Store Connect
- **Estimated scope**: 两次发布——iOS 首发时改价，付费墙与 [002](002-records-life-focus.md) 的 P1 同版
- **相关**: [002](002-records-life-focus.md) 定义了什么能被墙、什么永远不能；本文件定义怎么卖

## 一句话

App Store 免费下载，欢迎页之后展示一次可跳过的付费页，提供 7 天试用，之后按月 / 年 / 终身
订阅。**倒计时本体永久免费**，卖的是记录、人生视图与专注。

## 必须先说清的一个事实：通用购买绑住了两端

这是本方案唯一的硬约束，先摆在最前面：

- iOS 与 Mac App Store 共用**同一个 App 记录**：bundle id
  `com.rainif.offworkcountdown.macappstore`，App Store id `6802803318`。
- Mac App Store 上架的是 `src-tauri` 打出来的包，iOS 上架的是 `src-mobile/ios` 的 SwiftUI 包。
  这是 [ADR-MOBILE-D0](../docs/ADR-MOBILE-D0.md) 已锁定的通用购买决策，`check:ios` 也在断言
  这个 bundle id。
- 通用购买 = 一个记录 = **一个价格**。当前定价 US$0.99 / ¥8 买断。

因此 **iOS 改成免费下载，Mac App Store 上的 Tauri 版必然同时变免费**，做不到一端收费一端免费。

**已定：接受这个连带后果，整个记录改为免费 + IAP。** 代价是放弃 Mac 端的买断收入——而 Mac 端
至今的销量是 1 单，买家是作者本人，所以实际损失为零。想在 Mac 上使用记录功能的人，走 iPad
版在 Apple Silicon Mac 上运行这条路径。

**没有历史买断迁移负担。** iOS 尚未上架，macOS 唯一一单是作者自己，所以本方案**不实现**
`AppTransaction.originalAppVersion` / cutoff 那一整套历史用户判定：它是一段不可回测、
sandbox 里还给不出可信值的复杂逻辑，为一个已知为空的用户群写它没有意义。真要照顾那一单，
发一个兑换码比写一套判定便宜得多。

## 免费与付费的边界

这张表是本文件与 [002](002-records-life-focus.md) 的接口，两边必须一致。

分三层。第一版把「免费」和「付费」直接对立，结果是同一个实体（当日覆盖）一边被写成永久
免费的临时调班、一边被写成付费的单日编辑。三层才说得清。

**一、免费运营数据——始终可创建、可编辑。** 这些是让倒计时正常工作的输入，不是历史资产：

| 能力 | 说明 |
| --- | --- |
| 下班倒计时、排班设置 | 应用的本体 |
| **今天及未来**的当日覆盖（临时调班、请假、补班） | 它服务的是「明天几点下班」，属于运营输入 |
| 日历例外（节假日 / 补班标记） | 同上 |
| 薪资推算与今日收入、生物识别门禁 | 现有能力，不回收 |
| 小组件、实时活动、通知与微休息提醒 | 现有能力，不回收 |
| 分享图、主题与语言 | 现有能力，不回收 |

**二、数据权利——始终可达，不需要付费也不需要试用。**

| 能力 | 说明 |
| --- | --- |
| 已有记录的基础只读查看 | 一个朴素的列表即可，不是付费的图表 |
| 完整导出（JSON） | 见 002 的导入导出契约 |
| 删除单条 / 全部 / iCloud 副本 | 见 002 的隐私承诺 |

**三、付费能力——试用或订阅。**

| 能力 | 说明 |
| --- | --- |
| 记录 Tab 的周 / 月 / 年图表与统计 | 「回头看」的主体 |
| **过去日期**的当日覆盖编辑 | 修历史是回顾能力，不是运营需要 |
| 人生视图 | |
| 任务与专注（P2） | |
| iCloud 同步 | 到期后停止同步，本地数据不动 |
| 新观察日志的采集 | 见下方 |

### 到期之后到底发生什么

- 第一、二层照常，一点不减。
- 第三层停止。iCloud **停止同步**但不迁移、不删除，本地数据原样留着，重新订阅即恢复。
- **停止采集新的观察日志。** 初稿在这里写错了：当时的理由是「否则重新订阅时历史会留下
  补不回来的洞」，但 [002](002-records-life-focus.md) 明确写着观察不参与聚合、缺一段也不
  构成历史空洞。理由不成立，剩下的就只是「用户看不到任何收益，应用还在记录他的使用
  行为」——那不该做。已有的观察照常保留、可查看、可导出、可删除。
- **付费墙只加在 UI 层，永远不加在写入层。** 这条仍然成立，只是它管的是第一层：到期后用户
  改明天的班、标个补班，照样写得进去。

## 定价

| SKU | 国区 | 外区 | 说明 |
| --- | --- | --- | --- |
| 月 | ¥6 | $1.99 | 最低门槛，主要作用是让终身显得划算 |
| 年 | ¥25 | $9.99 | ≈ 4.2 个月，年比月省一半多 |
| 终身 | ¥58 | $24.99 | ≈ 2.3 年，第三年回本；国区用户偏好买断，这是主推 |

外区按当地购买力定价而不是汇率换算，这是 App Store 的普遍做法。

### 竞争力评估

**¥58 对现在的 App 贵，对 P1 之后的 App 不贵。** 国区单一用途工具的终身价大致落在
¥18–¥68 这个带上，¥58 属于中上但不离谱。真正的问题不是数字而是**卖的是什么**：今天这个
App 是「倒计时 + 薪资推算 + 小组件」，¥58 硬墙很难成立；等记录、人生视图与专注都在了，
同样的 ¥58 面对的是一个完整产品。

所以定价不变，**变的是开墙时机**——见下方发布顺序。

风险项，需要在上线后观察而不是现在拍板：

- 国区用户对小工具订阅的抵抗力强于欧美，月订阅的转化可能显著低于终身。如果终身占比
  超过八成，说明月/年订阅只是在给终身做锚，这不是坏事，但不要再为订阅追加功能。
- 这个 App 有很强的一次性传播流量（小红书一类）。「倒计时永久免费」正是为了不把这批
  流量在第 8 天全部关在门外。

## 试用：7 天

- 7 天正好覆盖一个完整工作周，价值已经展示完毕，决策不拖延；也让转化数据回来得更快。
- 试用是 App Store Connect 订阅组里的 **introductory offer**，不是代码里的逻辑。代码只负责
  读取当前 entitlement，不自己计时。
- **一个订阅组只能用一次 introductory offer**，所以试用只能挂一个商品。**挂年订**，付费页
  的默认 CTA 也是年订：试用结束直接转 ¥25，客单价最高、churn 最低。月订与终身仍然可选，
  只是没有试用。
- **资格必须查询而不是假设。** 用 StoreKit 的资格结果决定要不要显示「7 天免费试用」字样——
  已经用过试用的用户看到的必须是直接的价格，否则是误导，也会被审核挑出来。
- 终身买断是非消耗型商品，不参与试用。
- 必须用 StoreKit Configuration 文件在本地测通，并在真实 TestFlight 场景复验一遍。

## 付费页出现在哪里

1. **欢迎页之后展示一次，可跳过。** 介绍记录与人生视图，提供 7 天试用入口。跳过后直接进入
   倒计时，不再自动弹出。这一步的作用是让每个新用户都知道你在卖什么，而不是拦住他。
2. **真正的墙在记录 Tab 后面。** 未订阅用户点进记录 Tab 时展示付费页。
3. 设置页常驻一个入口，用于订阅、恢复购买与管理订阅。

免费用户在记录 Tab 里究竟看到什么（完全遮住 / 看当周 / 看一张模糊的年视图）还没定，见
「尚未决定」。

## 技术选型：直接用 StoreKit 2，不接 RevenueCat

RevenueCat 的价值在跨平台（安卓 / Web 订阅）、定价 A/B、跨端账号打通与收据校验托管。这个
项目一个都用不上：只有 Apple 平台、只有 3 个 SKU、没有服务端。而它的成本是真实的：它是
第三方服务，会把用户标识与购买记录发到**自己的**服务器，因此隐私标签要新增第三方 SDK 的
数据收集申报、要补 SDK 隐私清单，也要改引导页文案。用 StoreKit 则只与 Apple 通信，不引入
第二个数据接收方。

以后真要卖安卓或做定价实验时再迁不晚——RevenueCat 支持接管已有的 StoreKit 购买。

### 但这不代表「完全不发网络请求」——旧承诺必须改

初稿把「不接 RevenueCat」写成了「所以能保住不发网络请求」，这是错的。`Product.products(for:)`
本身就是向 App Store 取商品与本地化价格，而付费页在欢迎页之后会展示给每一个新用户——
也就是说，即使用户从不进入记录 Tab、从不开启 iCloud，首次启动也会发生 StoreKit 网络访问。

两件事要做：

1. **文案改成准确的**，全部 19 个 locale：

   > 倒计时和本地数据可离线使用。应用仅在加载购买信息、恢复购买，或你主动开启 iCloud
   > 同步时连接 Apple 服务；你的工作与薪资数据不会发送给开发者。

2. **把商品加载推迟到用户真的要看价格时。** 欢迎页之后那一屏可以先渲染静态介绍，只有用户
   点「查看价格 / 开始试用」才调 `Product.products(for:)`。这样跳过付费页的用户在首次启动
   全程仍然不联网——文案照上面写，但实际行为比文案更克制。

实现边界：

- 使用 StoreKit 2 的 `Transaction.currentEntitlements` 与 `Product.SubscriptionInfo`；部署目标
  足够高，不需要兼容旧 API。
- **权益判定收敛在一个入口**，不在各个视图里散落 `isPro` 判断。这既是可读性，也让将来换实现
  只改一处。
- 状态必须区分「已验证为无权益」与「尚未验证 / 暂时失败」，不能把网络失败当成未订阅把用户
  锁在外面，也不能「第一次看到就永久缓存」把未验证当成已购买。
- 价格一律用 `displayPrice` 等 StoreKit 提供的本地化字符串，不在 19 个 locale 里硬编码货币。
- 付费页必备要素（Apple 3.1.2 审核会逐条看）：本地化价格、订阅周期、试用时长与**试用后的
  价格**、恢复购买按钮、服务条款与隐私政策链接、清晰的自动续费说明。缺一项就是被拒的
  理由，**不能「零 UI 发版」**。
### 权益状态机

「有没有订阅」不是一个布尔值。判定必须覆盖下面每一行，缺一行就是一类线上事故：

| 状态 | 是否授权 | 说明 |
| --- | --- | --- |
| `subscribed` | 是 | 正常订阅中（含试用期内） |
| `inGracePeriod` | **是** | Apple 正在重试扣款，此时切断是把用户当欠费处理 |
| `inBillingRetryPeriod`（无宽限期） | 否 | 已进入重试且没有宽限期，按未订阅处理 |
| `expired` | 否 | 正常到期 |
| `revoked` | 否 | 退款或家庭共享被撤销 |
| 交易带 `revocationDate` | 否 | 退款，无论商品类型；终身也会被撤销 |
| 终身（非消耗型，未撤销） | **是，且永久** | 不参与续期状态判定 |
| 购买待批准（Ask to Buy / pending） | 否，但**不是错误** | 显示「等待批准」，不要弹失败也不要当未订阅劝购 |
| 尚未验证 / 网络失败 | 沿用上次已验证结果 | 既不锁人，也不把未验证当已购买 |

**「退款」和「试用期内关掉自动续费」不是同一件事**，不能用一套分支处理：前者是撤销
（`revocationDate`，权益立刻消失），后者只是不再续期（当前周期内仍然 `subscribed`，权益
保留到周期末）。Apple 把续期状态与撤销日期分成两套 API，实现上也必须分开读。

另外两条实现要求：

- **常驻 `Transaction.updates` 监听器**，在应用启动时就挂上。App 外发生的续期、退款、家庭
  共享变更只会从这里来。收到已验证交易后必须 `finish()`，否则会被反复投递。
- **验证失败的交易一律不授权**，不要「先放行再补验」。

### 终身与订阅可能同时存在

终身是非消耗型商品，订阅会一直续期到用户自己去取消——**买终身不会自动取消已有订阅**。
初稿写的「买过终身就永远不再展示任何订阅入口」会把用户的管理入口一起藏掉，结果是他继续
被扣款却找不到地方停。正确做法：

- 已有活跃订阅的用户点终身时，**购买前**明确提示：这不会自动取消你现在的订阅，买完请去
  「管理订阅」关闭它。
- 购买后隐藏的是**推销入口**（价格、CTA），**保留管理订阅入口**，并在设置页显示「你同时
  有一个仍在续期的订阅」直到它结束。
- 只有确认没有活跃订阅时，才彻底收起与订阅有关的一切。

## Mac / Tauri 端怎么办

- Mac App Store 版随记录改为免费，**不做 IAP**，功能维持现状。它本来就不参与 002 的记录能力。
- 桌面端继续与 Windows 一并更新，但更新频率低于 iOS。
- 改价前需要清理 Tauri 端与官网上任何暗示「付费应用」的文案与截图。
- 想在 Mac 上用记录功能的人，走 iPad 版在 Apple Silicon Mac 上运行。

## 发布顺序

### 第一步：iOS 首发（无墙）

- 整个 App 记录改为免费。Mac App Store 的 Tauri 版随之免费。
- iOS 首次上架，不含 IAP、不含付费页、不含记录功能。
- 目标是攒评价与口碑，也验证 iOS 端本身的稳定性。

### 第二步：与 002 的 P1 同版

- 上 IAP（月 / 年 / 终身）、付费页、7 天试用与记录 Tab 的墙。
- **首发期下载的用户一视同仁**，同样需要试用或付费才能使用记录。理由：记录是全新功能，
  他们没有失去任何已有的东西，倒计时也依然免费；而做「早期用户永久解锁」需要引入一个
  基于安装时间的不可回测判定，正是本方案刻意删掉的那类复杂度。
- 付费页、订阅商品名与描述纳入 19 个 UI locale。

## 尚未决定

1. 免费用户在记录 Tab 看到什么才有购买欲：完全遮住、只看当周、还是看一张模糊的年视图？
   与 [002](002-records-life-focus.md) 的未决 2 是同一个问题，两边同时定。
2. 终身买断是否开启家庭共享（Family Sharing）？开了对口碑友好，但一份卖给最多六个人。
3. 订阅组、商品 ID 与显示名的命名方案。
4. 是否准备 offer code，用于给早期反馈者、媒体或那一单历史买断用户补偿。
5. 退款与「试用期内取消」的应用内表现：是立刻收回权益，还是走完当前周期。

## 验收场景

1. 全新安装：欢迎页 → 付费页 → 跳过 → 倒计时完全可用，无任何功能受限提示。
2. 开始 7 天试用：记录 Tab 立刻可用，设置页显示试用剩余天数与到期日。
3. 试用到期未续：记录 Tab 回到付费页；倒计时、排班、薪资、小组件照常；导出与删除入口仍可达。
4. 订阅中途取消但周期未结束：权益保留到周期末，不提前收回。
5. 已有活跃订阅时购买终身：购买前收到提示，购买后管理订阅入口仍在，直到旧订阅自然结束。
6. 扣款失败进入宽限期：权益不中断；宽限期结束仍未成功才收回。
7. 退款 / 家庭共享撤销：权益立即收回，且与「取消自动续期」走不同分支。
8. Ask to Buy 待批准：显示等待状态，不弹购买失败，也不继续劝购。
9. 已用过试用的用户打开付费页：不显示「7 天免费」，直接显示价格。
10. 应用在后台时发生续期或退款：`Transaction.updates` 收到后权益随之更新。
11. 换设备后恢复购买：不重新付费即可恢复权益。
12. 无网络启动：不把网络失败当成未订阅，已验证过的权益仍然生效。
13. 跳过付费页的用户首次启动全程：不发生 StoreKit 网络请求。
14. Sandbox / TestFlight：试用、续订加速周期、退款各跑一遍，不用 sandbox 的版本号做任何判定。
15. 订阅到期：停止采集新观察、停止 iCloud 同步；排班与未来临时调班照常可编辑；只读查看、
    导出与删除入口仍可达；本地数据一条不少。
16. Mac App Store 版：免费下载，无 IAP 入口，无任何指向 iOS 订阅的死链。

# 工作地點自動化 · P0 真機測試指南

> 給測試者的操作清單。結果請匯出記錄檔交回，由開發端整理進
> [021-workplace-automation-capability.md](021-workplace-automation-capability.md)。
> 測試版本：TestFlight **DoneAt 3.3.0 (2)**（或之後的內部測試版），僅限內部測試，含工作地點探針與「設定 → 工作地點自動化」。

## 這次要回答的問題

在你的 iPhone 上，進出公司時系統能不能把 App 叫醒並通知它，延遲多久、多常漏掉或誤報。這決定正式功能能不能做、預設參數怎麼定，以及對用戶能承諾到什麼程度。

探針**只記錄，不會改你的工時、不會發通知**。

## 一、準備（約 10 分鐘，只做一次）

> 探針畫面是開發用介面，按鈕文字為簡體中文；下文引號內的文字與畫面一致。

- [ ] 在 App 內先匯出一份記錄備份（記錄 → 匯出）。TestFlight 版會取代手機上現有的 DoneAt；正式 iCloud 照常同步，備份只是保險。
- [ ] 打開 TestFlight，安裝 **DoneAt 3.3.0 (2)**。
- [ ] 打開 DoneAt → 設定 → 關於，**長按「DoneAt」字樣兩次**，進入「工作地点探针」。頂部應有橙色「內部測試版」橫幅。
- [ ] 點「开启探针并请求“始终”授权」→ 系統詢問時選「使用 App 期間允許」；之後若再詢問，選「改為永遠允許」。
- [ ] 到 iPhone **設定 → 隱私權與安全性 → 定位服務 → DoneAt**，確認為「**永遠**」，且「**精確位置**」開啟。
- [ ] 回到探針頁，確認「定位授权」顯示 `always`、「精度」顯示 `full`。
- [ ] **在公司的座位上**點「把当前位置加为地点」（內圈先用預設 200 米）。看到「地点」區出現 `Place 1 · 200/300 米` 即完成。
- [ ] 記下目前電量與日期，作為耗電對照的起點。

> 如果公司大樓很大、或入口離座位很遠，記下大概距離；必要時之後再調整半徑。

## 二、每天固定要做（約 2 分鐘）

1. **正常通勤**：手機照常放口袋、照常鎖屏，**不要刻意打開 DoneAt**。
2. **記下真實時間**（填在下方〈測試日誌〉）：大約幾點進公司、幾點離開、中午有沒有外出。
3. **晚上匯出**：探針頁 → 「生成导出文件（不含坐标）」→ 「分享导出文件」→ AirDrop 到 Mac 或傳給自己，檔名加上日期，例如 `probe-2026-11-09.tsv`。
4. 把當天檔案和日誌一起交回（放在同一個資料夾即可，告訴我路徑）。

匯出檔只有地點名稱與半徑，**沒有座標**。

## 三、測試情境

先用 2–3 天做**基本情境**，確認一切正常後再穿插**刻意情境**。每做一個刻意情境，在日誌的「情境」欄寫上編號。

### 基本情境（每天自然發生）

| # | 情境 | 怎麼做 | 預期 |
|---|---|---|---|
| A1 | 鎖屏進公司 | 正常上班 | 出現 `Place 1/inner satisfied` |
| A2 | 鎖屏離開公司 | 正常下班 | 出現 `Place 1/outer unsatisfied` |
| A3 | 前台進出 | 某次進出時剛好開著 DoneAt 即可 | 同上，延遲通常較短 |

### 刻意情境（各做至少一次）

| # | 情境 | 怎麼做 | 預期／關注 |
|---|---|---|---|
| B1 | 系統回收 App | 前一晚起不要打開 DoneAt，睡前多開幾個大型 App（相機、遊戲、地圖），隔天直接上班 | 記錄出現 `launch` 緊接 `event`，中間沒有 `became active`：代表系統在背景叫醒了 App |
| B2 | 划掉 App | 出門前在多工畫面把 DoneAt 往上划掉，然後上班 | **預期收不到**，這是 iOS 限制；如實記錄即可 |
| B3 | 重新開機 | 早上出門前重開機，**先不要解鎖**走一段路，再解鎖，然後上班 | 解鎖前預期收不到；解鎖後的進公司能否收到 |
| B4 | 午間外出 | 中午離開大樓吃飯再回來 | 記錄離開與返回；正式功能只會當作「暫時外出」 |
| B5 | 路過 | 下班後或週末經過公司附近但不進去 | 是否誤報進入 |
| B6 | 長時間靜止 | 在辦公室一整天不太走動 | 是否出現莫名的離開／進入 |
| B7 | 權限降為「使用期間」 | 某天出門前改成「使用 App 期間」，上下班後再改回「永遠」 | 應出現 `insufficientlyInUse` 或 `authorizationDenied` 之類標記，**不應**出現假的離開 |
| B8 | 關閉精確位置 | 某天關掉「精確位置」，上下班後再開回 | 應出現 `accuracyLimited` 或 `fullAccuracyDenied` |
| B9 | 5 個地點 | 基本情境穩定後，點「补足到 5 个地点（10 个条件）」，再通勤 1–2 天 | 不應出現 `conditionLimitExceeded`；Place 1 照常觸發 |
| B10 | 網路條件 | 某天通勤時關掉 Wi-Fi，或在訊號差的地方進出 | 只記錄實際結果 |
| B11 | 耗電對照 | 探針開啟期間記 2 天的每日耗電；之後「关闭探针」再記 2 天 | 兩段的耗電差異（設定 → 電池裡 DoneAt 的占比也可截圖） |

### 建議的日程（可依實際情況調整）

| 天 | 內容 |
|---|---|
| 第 1–3 天 | 只做基本情境 A1–A3 |
| 第 4 天 | B1 系統回收 |
| 第 5 天 | B4 午間外出 + B6 長時間靜止 |
| 第 6 天 | B3 重新開機 |
| 第 7 天 | B2 划掉 App |
| 第 8 天 | B7 權限降級 |
| 第 9 天 | B8 精確位置 |
| 第 10–11 天 | B9 五個地點 |
| 任意時間 | B5 路過、B10 網路 |
| 最後 4 天 | B11 耗電對照（2 天開、2 天關） |

**目標：至少 10 個完整上下班週期。** 週期不必連續。

## 四、怎麼看記錄（不看也可以，交回即可）

探針頁每筆記錄兩行：

```
08:53:12 event Place 1/inner satisfied +41s
background · locked · always · full
```

- `inner satisfied` = 進入內圈（到公司）；`outer unsatisfied` = 離開外圈（離開公司）。
- `+41s` = 系統察覺到 App 收到之間的延遲。
- `background · locked` = 收到時 App 在背景、手機鎖著，這是最重要的情況。
- `launch` = App 被啟動；若後面緊接 `event` 而沒有 `became active`，表示是系統在背景叫醒它。
- 看到 `conditionLimitExceeded`、`authorizationDenied`、`serviceSessionRequired` 等標記時，請在日誌備註。

## 六、遇到狀況時

| 狀況 | 處理 |
|---|---|
| 找不到探針入口 | 確認裝的是 TestFlight 3.3.0 (2)；在「關於」頁長按「DoneAt」**兩次**，每次約半秒 |
| 「定位授权」不是 `always` | 到 iPhone 設定改為「永遠」，再回探針頁看是否更新 |
| 加地點時轉很久 | 到窗邊或室外重試；30 秒內拿不到 100 米以內的位置會放棄並記一筆 `error` |
| 一整天都沒有事件 | 先確認探針「状态」是「运行中」、地點仍在；當天照常匯出並在備註說明 |
| 想重設地點 | 「移除全部地点」後重新在座位上加入 |
| 記錄太多 | 匯出後才「清空记录」；探針最多保留最近 3,000 筆 |

## 七、測試結束

- [ ] 最後一次匯出並交回。
- [ ] 探針頁點「关闭探针」→「移除全部地点」。
- [ ] 視需要到 iPhone 設定把 DoneAt 定位權限改回「永不」。
- [ ] 從 App Store 重新安裝正式版 DoneAt（或等下一個 TestFlight 版本）。

## 交回清單

- [ ] 每天的匯出檔（`probe-YYYY-MM-DD.tsv`）
- [ ] 填好的測試日誌與耗電表
- [ ] 手機型號與 iOS 版本（設定 → 一般 → 關於本機）
- [ ] 任何覺得奇怪的地方，越具體越好（時間、在哪裡、當時在做什麼）

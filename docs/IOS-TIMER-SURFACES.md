# iOS 计时页：形态、布局与班次逻辑

本文是计时页的**目标口径**，2026-08-27 面试锁定，由 [007](../plans/007-ios-stable-before-subscription.md) 落地。Swift 实现以本文为准。

排班、午休、剩余时间和休息日判定仍以 `lib/countdown.ts` 为唯一实现；Swift 只消费 `NativeShiftSnapshot` 并选择界面。Widget / Live Activity / 通知用同一套 Store 标记，但各自有平行投影，不驱动计时页的阶段枚举。

计时 Tab 是钟，不是设置台。欢迎页配完最小集后上手即用；以后改设置只走设置 Tab。

源码入口（落地后；现名可能随重构改）：

| 职责 | 文件 |
|---|---|
| 壳层选择（手机 / 横屏 / iPad） | `RootView.swift` |
| 计时页状态 | `TimerVisualPhase.swift`、`OffWorkStore.swift` |
| iPhone 竖屏 | `TimerDesignView.swift`、`TimerStatusViews.swift` |
| iPhone 横屏 | `PhoneLandscapeView.swift` |
| iPad | `TabletDesignView.swift` |
| 提前下班 / 提前上班 / 手动计时 / 加班 | `OffWorkStore.swift`、底栏与横幅 |
| 上下班时刻 | 欢迎页最后一页 + 排班设置页（**不再**是计时首页英雄卡） |

---

## 1. 先看结论

有排班时，计时页只在下面几态之间转。没有「配置页」，没有「停止倒计时」。

| 态 | 钟在数什么 | 主操作 |
|---|---|---|
| **上班倒计时** | 距上班；进度按已经过的上班前时段从 0 增到 100 | 通栏「提前上班」+ 分享 |
| **下班倒计时** | 距下班；午休穿插时数字改数回来；加班穿插时数到加班结束 | 提前下班 / 加班 / 分享；「接下来」 |
| **结算** | 今日已下班 | 加班 / 分享；提前下班可撤销。无「返回」 |
| **休息** | 弱倒数 + 同口径进度（目标仍是下一班上班点）+ 本周 / 本年结算 | 「手动计时」。不要「接下来」 |
| **未排班** | 每天问今天上不上 | 也叫「手动计时」；开始后落入上 / 下班倒计时 |

**规则错误**不是一态职能：排班仍在，计时 Tab 上横幅说明，去设置或等规则包恢复。不要靠停表离开。

午休和加班不是计时页的「职能种类」，是下班倒计时里的穿插。健康提醒 / 微休息只出现在「接下来」。

设备壳层（Size Class，**不是** `UIDevice`）。**先看高度再看宽度**：

| 条件 | 壳 | 典型设备 |
|---|---|---|
| `verticalSizeClass == .compact` | `PhoneLandscapeShellView` | 所有 iPhone 横屏，含 Plus / Max |
| regular 高 + `horizontalSizeClass == .regular` | `TabletShellView` | iPad 全屏（竖屏与横屏） |
| compact 宽 + regular 高 | 系统 `TabView` | 所有 iPhone 竖屏；iPad 很窄的分屏 |

iPad 详情栏 &lt; 620 pt 时回落到 iPhone 竖屏计时布局（内容限 440 pt）。≥ 620 pt 才用 iPad 专属密度。侧边栏固定 290 pt。

## 2. 状态如何判定

产品顺序（短路）。实现可以仍用一个 `TimerVisualPhase` 枚举，但不得再把「未启动」映射成配置页。

```
欢迎页未完成？                    → 欢迎页（不是计时态）
scheduleMode == .off
  且今天没有一次手动计时？        → 未排班
快照失败？                       → 规则错误横幅（排班不停止）
提前下班仍覆盖当前班
  或 remainingMs <= 0
  或 结束落在的日历日尚未过完？   → 结算
今天按排班不是工作日
  且没有手动计时？                → 休息
now < startAtMs？                → 上班倒计时
否则                             → 下班倒计时
                                   （空隙内：午休穿插）
                                   （已设加班且 elapsed ≥ 计划时长：加班穿插）
```

提前下班必须先于休息：休息日手动计时后再提前下班，仍应落在结算而不是「好好休息」。夜班结束后 `getShiftBounds` 会跳到下一场窗口；计时页用同一条规则束把「结束落在的日历日尚未过完」的那一班当作结算快照，而不是周六晚上的幻影班。

`snapshot.isWorkday` 按**班次开始日期**，不是「现在」的日历日。夜班跨零点时，凌晨仍属于前一晚的班。

`remainingMs` / `elapsedMs` 按 **segments 有效工时**。午休空隙不推进进度、不计薪。加班延长最后一段结束点：进度可以超过 100%，计薪按「已过有效时间 / 计划有效时长」线性外推，没有倍率。

上班倒计时和休息日的大数字用距**下一班上班点**的剩余（`heroRemainingMs` 那条口径），不是整班 `remainingMs`。

## 3. 各态长什么样

以 iPhone 竖屏为基准。其他壳如何改写，见第 4 节。

### 3.1 上班倒计时

工作日（或手动计时把今天当成工作日），且 `now < startAtMs`。

- 大数字：距上班还有。
- 进度条：目标工作日的 0 点为 0，上班点为 100，按已经过的时间增长。00:08 距 09:00 还有近 9 小时时应约为 1.5%，不能把「剩余比例」画成 98.5%。大数字与条都由规则桥返回，分享、Widget 与三个 App 壳不得各算一版。
- 「接下来」：何时上班、午休、下班。
- 底栏：通栏主按钮「提前上班」，旁边分享。没有提前下班、没有加班。
- 摘要：今日班次时段；开了薪资则今日已赚（显隐规则不变）；有排班则本周 / 本年。

**提前上班**：二次确认。把今天的开始改成现在，下班时刻不变（今天变长）。工时按用户改过的算，收入仍按排班日薪（[002](../plans/002-records-life-focus.md)）。不做迟到入口。可在下班倒计时上撤销：开始回到排班点；若仍早于计划开始，回到上班倒计时。上班倒计时切到下班倒计时走态过渡，不要整页硬切。

### 3.2 下班倒计时

班已经开始、尚未结束。

- 大数字：有效剩余工时。说明「今天的班次还剩」。
- 进度条正常走。
- 「接下来」+ 底栏：提前下班 / 加班 / 分享。
- 可在计划结束前登记加班（最早 `max(计划结束, 现在) + 15 分钟`）。登记后本态不变，有效工时吃完计划时长后才改加班穿插。

**午休穿插**（`getActiveBreakEndAtMs` 非空）：不切独立午休页。大数字改数空隙结束（回来），文案暂停至几点；整班进度条暂停。底栏三键仍在。「接下来」标出午休。未到或已过空隙，回到数下班。

**加班穿插**（已有 `overtimeEndAtMs` 且 `elapsedMs >= plannedDurationMs`）：胶囊或说明「加班到 {时刻}」；数字数到加班结束；进度加班色；加班键改成「调整加班」。加班结束 → 结算。加班结束日的次日零点清掉加班标记。

**提前下班**：只在本态。二次确认。写入今天的结束修正（计时本地标记，P0A 再投影成当日覆盖）。进入结算。不清加班边界。不是请假——今天不上班走设置。

### 3.3 结算

计划工时耗尽，或用户提前下班。**两者都是下班**；用户修正优先，自动结束是没按按钮时的兜底。

- 标题「今日已下班」（可重放庆祝）。
- 计划结束：进度 100%。提前下班：停在按下那一刻，数字来自按下时冻结的规则快照。
- 提前下班：可撤销横幅。撤销窗口 = 结束落在的日历日结束前（见 6.1）。过缝不可撤，交给以后的记录 Tab。
- 底栏：加班、分享。从这里设加班 = 「其实还没走」，清掉提前下班。
- **没有「返回」。** 不要 `dismissCompletedShift`，不要回到配置页。

### 3.4 休息

有排班、今天按排班不是工作日、没有手动计时。`scheduleMode == .off` 不会进入本态。

- 文案对齐小组件：`好好休息 · 距离下次上班`。
- 大数字仍连续倒数到下一班上班点。进度条按已经过的休息区间从 0 增到 100；到目标工作日 0 点切入上班倒计时后，新一段再从 0 增到上班点。这样跨周末不在每天 0 点重算或倒退，也不会在还剩整夜时显示接近 100%。视觉较弱。
- 本周已做 / 已赚、本年同类信息。不要「接下来」，不要工作日设置入口。
- 底栏通栏「手动计时」，二次确认。沿用已有上下班时刻把今天当成工作日。

工作日零点起，同一条倒数改成普通上班倒计时（只换文案和视觉权重）。见 6.1。

### 3.5 未排班

欢迎页或设置选了「先不排班」（`scheduleMode == .off`）。

- 每次打开问今天上不上。主按钮也叫「手动计时」。
- 上：用已有时刻；已过开始点则直接下班倒计时，否则上班倒计时。
- 结算后次日零点回到本态。没有休息态（没有排班就没有「按排班的周末」）。
- 开始之前没有分享。

### 3.6 规则错误

快照为 `nil`（缺 `CountdownRules.js` 等）。横幅 + 说明，排班不停止。正常构建会生成规则包；新鲜 clone 需 `npm run build:ios-native-rules`。

## 4. 设备壳如何改写同一态

### 4.1 壳怎么选

```
欢迎页未完成
  → OnboardingView
verticalSizeClass == .compact
  → PhoneLandscapeShellView（左侧 62 pt 轨道，计时 / 设置）
horizontalSizeClass == .regular
  → TabletShellView
否则
  → TabView：计时 | 设置
```

欢迎页仍按 `horizontalSizeClass == .regular` 走宽栏，与计时壳的 compact-height-first 不是同一道门——改欢迎页最后一页时不要误用计时壳的门。

### 4.2 iPhone 竖屏

`TimerDesignView` 按第 3 节切换。上班 / 下班倒计时带「接下来」和底栏；结算、休息、未排班没有「接下来」。

### 4.3 iPhone 横屏

没有独立午休 / 加班整页（已经是仪表 + 文案），与第 3 节穿插口径对齐。横屏可以没有「接下来」列表。结算 / 休息 / 未排班 / 错误回落宽版计时表面。已下班宽>高则两栏。

**不要再画配置页**（`LandscapeSetupView` 一类）。

### 4.4 iPad

窄栏回落（详情 &lt; 620 pt）= 竖屏那套。宽栏：

- 上班 / 下班倒计时：工作台（侧边栏开）或沉浸式（侧边栏关）。
- **沉浸式必须仍能碰到提前上班、提前下班、加班、分享、取消手动计时。** 不能只活在收起的侧边栏里。
- 结算 / 休息 / 未排班：共用表面；侧边栏关时左上角打开侧边栏，避免出不去。

侧边栏在计时 Tab：今日班次、午休标签、今日已赚（眼睛可放这里）。设置 Tab：迷你倒计时，避免切走后数字停住。

### 4.5 态 × 布局

| 态 | iPhone 竖屏 | iPhone 横屏 | iPad 侧边栏开 | iPad 侧边栏关 |
|---|---|---|---|---|
| 上班倒计时 | 数到上班 + 接下来 + 提前上班/分享 | 仪表 + 提前上班/分享 | 工作台 | 沉浸式，仍须有主动作 |
| 下班倒计时 | 大数字 + 接下来 + 三键；午休/加班穿插 | 同一仪表，文案区分 | 工作台 + 胶囊 | 沉浸式 + 胶囊，仍须有三键入口 |
| 结算 | 庆祝页；撤销横幅 | 宽>高则两栏 | 共用庆祝页 | 共用 + 打开侧边栏 |
| 休息 | 弱倒数 + 周/年 + 手动计时 | 共用 | 共用 | 共用 + 打开侧边栏 |
| 未排班 | 今天上不上 + 手动计时 | 共用 | 共用 | 共用 + 打开侧边栏 |

同一态里还会变：薪资开/关、午休开/关（进度条午休墙、「接下来」里的行）、时间线展开（竖屏 / iPad 工作台藏摘要卡）、已赚隐藏（显示要生物识别）。

## 5. 欢迎页与设置

### 5.1 欢迎页最小集

现有故事页保留。**最后一页换成班次表单**，不再叫完「开始设置」却把人丢进计时首页。

必须配完才能进计时页：

- 上下班时刻
- 排班方式：固定星期、单双休 / 大小周、轮班轮休，或「先不排班」
- 选了固定星期则至少勾一天

午休、薪资、提醒、主题仍在设置。默认 09:00–17:00、周一到周五可预填，但必须能看见、能改。欢迎页最后一页与其它欢迎页一样上下居中；内容超出时再滚动。

已完成过欢迎页的人**不再走欢迎页**；已有时刻和排班直接进四态。配置入口只剩设置 Tab。

### 5.2 设置是唯一改班次形态的地方

上下班时刻放在**排班设置页顶部**（计时首页英雄卡不再可改）。设置首页「排班」行点进去就是时刻 + 工作日 + 模式。

排班与午休页采用显式草稿：编辑控件只改草稿，点右上角保存才提交；带未保存草稿返回时，只在返回按钮上挂系统 `confirmationDialog` 询问是否放弃。选择器合上不提交，也不询问「今天也改」。

点保存后先由规则桥判断草稿是否还能改变今天：只有确实会改变今天剩余班次 / 午休边界时，才弹系统 Alert，三项**无预选**：「只从下一班起」「今天也改成这样」「取消」。如果两种选择对今天已没有区别，直接按「只从下一班起」保存，不制造一次无意义确认。

- 今天原班次已结束：新班次仍已结束或仍是休息 / 未排班，不问；新结束点会把今天重新变成未结束，才问。
- 今天是排班休息日：只改上下班时刻不问；工作日、排班模式、单双休 / 轮班等排班形态发生变化才问。休息日手动计时也不因单纯改时刻被打断。
- 午休：原午休和新午休都已经过去（包括此时关闭午休）不问；原午休仍未结束 / 尚未开始，或新午休会落在今天剩余班次内，才问。
- 这里不推导 `actualStart`。已经结束的当天若需要修正真实上班时间，留给 002 的人生板块手动修改。

「只从下一班起」覆盖层只作用于**当前这一班**。`nextShift*`、提醒的 `next:`、小组件未来班次走底图，不要把旧时刻写进未来一年。

「今天也改」会清掉当天的提前上班、提前下班、加班。弹层写清楚。不清掉休息日手动计时。

固定星期最后一天勾不掉。设置页已经有「先不排班」模式行，不再在工作日格子下重复那条旁注。欢迎页用模式行选择先不排班。

### 5.3 有排班就没有停止

欢迎页完成后，计时 Tab 只在上班倒计时 / 下班倒计时 / 结算 / 休息之间转。关掉排班 = 设置里改成「先不排班」（未排班态）。规则错误不是停表逃生口。

## 6. 修正、日历缝、跨日

### 6.1 结算何时让位（对齐小组件）

本班结束后、**结束落在的日历日**结束前 = 结算。次日零点：不是工作日 → 休息；是工作日 → 上班倒计时。加班越过零点时，这条缝看 **effective end**（`overtimeEndAtMs`），不是计划 `endTime`。

夜班周五 22:00–周六 06:00：周六 06:00 起仍是结算，直到周六 24:00；周日零点才好好休息。工作日看班次开始日，这条缝看结束落在的日历日。日班周一加班到周二 01:00：周二 01:00 后仍是周一那班的结算，直到周二下一班真正开始。

小组件已经：休息的日历日用 `widgetRestDay`（好好休息 · 距离下次上班），工作日零点改 `nextShiftLabelShort`。计时页用同一条缝。

提前下班的周五下午：当天结算，零点再进休息或上班倒计时。

### 6.2 三种修正怎么收回

| 修正 | 收回 |
|---|---|
| 提前下班 | 只在当天结算页撤销，过日历缝不可撤 |
| 提前上班 | 下班倒计时上撤销，开始回到排班点 |
| 手动计时（有排班的休息日） | **不能**用提前下班撤。进班后顶栏横幅「手动计时」+ 取消（二次确认），回到休息，今天仍是休息日 |

未排班点「手动计时」没有「取消回好好休息」。结束用提前下班或等到结算。

二次确认：提前下班、提前上班、手动计时、取消手动计时。设置里那问本身就是确认。上班倒计时切到下班倒计时走现有的态过渡（不整页硬切）。

### 6.3 标记写在哪

提前上班、提前下班、手动计时、设置里「今天也改」，在 [002](../plans/002-records-life-focus.md) P0A 的 `DayOverride` 落地前，写计时页本地标记（与现有 `earlyOff*` 同类）。必须能一对一投影成覆盖，不能变成第三套语义。本次不建记录层。

应用不记录迟到，下班倒计时上没有「其实这时才开始」。

### 6.4 跨日其它

- 手动计时绑定班次开始日的 day key；跨日或横幅取消会清掉。提前下班**不**清掉——那是这一班的结束，不是「今天没上过」。被手动计时的那天，汇总把这一天算进工作日集合。
- 提前下班绑定班次窗口，不绑定日历日。
- 未排班：结束日次日零点回到「今天上不上」。
- 时间线保留跨零点后仍属于本班的事件。

提前下班之后，标记进入 `scheduleSignature`：重排通知、结束 Live Activity、刷新 Widget。通知丢掉仍属于被结束班次的提醒；Widget 画「今日已下班」，不是休息日。

## 7. 分享

出现在：上班倒计时、下班倒计时（含午休 / 加班穿插）、结算。休息日和未排班开始之前没有分享。

卡片大数字、配文、进度条跟**屏幕上正在数的那个钟**走。心情贴纸保留。

| 态 | 配文 / 大数字 |
|---|---|
| 上班倒计时 | 距上班还有 X；进度按距上班 |
| 下班倒计时 | 「我还有 X 就下班」 |
| 午休穿插 | 数回来；「午休中，还有 X 回来」 |
| 加班穿插 | 数到加班结束；下班口径（加班是延长后的下班） |
| 结算 | 「我下班啦 / 已下班」；提前下班用冻结进度，不要顶格 100% |

链接只带**排班时刻**（`?s=0900-1700`），让别人套用一班。薪资、提前上/下、手动计时、今天的有效窗口都不进 URL。图片同样 salary-free。

## 8. 主路径

欢迎页完成、固定星期周一到周五 09:00–17:00、午休关闭：

1. 工作日零点到 09:00 → 上班倒计时。可提前上班。
2. 09:00 后 → 下班倒计时。午休打开且落在空隙里则穿插，结束回到数下班。
3. 17:00 → 结算。当天可再加班 → 加班穿插 → 再结算。
4. 班中提前下班 → 结算 + 可撤销；过零点不可撤。
5. 结算页加班 → 清提前下班，回到下班倒计时或加班穿插。
6. 周五结算后，周六零点 → 休息（弱倒数到周一 09:00）。可手动计时。
7. 周一零点 → 上班倒计时（同一条倒数，文案变强）。

未排班：每次打开「手动计时」决定今天有没有班。

## 9. 刻意不做成计时页职能的东西

- **健康提醒 / 微休息**：只在「接下来」。
- **分享页、加班表、时间选择器、设置里那问**：Sheet / 弹层。
- **薪资显隐、主题、语言、时间线展开**：态内开关。
- **迟到**：不捕捉、不命名、不给按钮。
- **请假 / 改历史**：设置或以后的记录 Tab，不用提前下班冒充。
- **Widget / Live Activity**：平行投影。休息用 `widgetRestDay` 缝；提前下班用 `.done` / complete，不是休息日。
- **配置页、应用配置、草稿时刻、`dismissedCompleted`、「停止倒计时」**：从计时 Tab 删除。

## 10. 维护时容易踩到的不对称

落地后仍须对齐各壳：

1. 午休 / 加班在竖屏是下班倒计时穿插，横屏本来就是一块仪表——不要只改竖屏又画回独立页。
2. iPad 沉浸式必须有主动作，不能只靠侧边栏。
3. 壳层先看 compact 高；欢迎页仍走 regular 宽。
4. 分享文案必须跟当前钟，禁止上班前用整班 `remainingMs` 说「还有 X 下班」。
5. 固定星期不允许空工作日集合。

规则或状态判定有变：改 `lib/countdown.ts`（或计时状态机），`npm test`，`npm run build:ios-native-rules`，在 iPhone 竖屏、横屏、iPad 侧边栏开/关、iPad 横屏上看一遍。提前下班须重排通知、结束 Live Activity、刷新 Widget。
